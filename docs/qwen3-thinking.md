# Qwen3 思考模式约定

## 已确定的项目约定

用户于 2026-10-27 要求：后续使用 Qwen3 做数学推理实验时，各参数规模均遵循对应模型的官方思考模式最佳实践。

- 对支持思考模式的 Qwen3，默认启用思考模式；0.6B、1.7B 和其他参数规模采用相同原则。资源预算通过批量、长度和训练方式调整。
- 实施前核对具体模型 ID、版本的官方模型卡、聊天模板和训练说明。思考模式支持情况以该模型为准；模型规模本身不决定开关。官方若有版本差异，按对应版本处理。
- 官方推理建议、项目训练目标和实验性损失掩码分别记录。推理采样建议不能自动决定 SFT 的监督范围。
- 抽样推理结果继续保存到文件，由用户自行查看；实际推理和训练按用户本轮授权执行。

## 当前混合思考 Qwen3 的官方推理参考

以下设置核对于 2026-10-27，适用于当前 Qwen3-0.6B、Qwen3-1.7B 所属的混合思考版本；换模型版本时重新核对。

| 项目 | 思考模式参考设置 |
| --- | --- |
| 聊天模板 | `enable_thinking=True` |
| 生成方式 | 采样，避免贪心生成 |
| 温度 | `temperature=0.6` |
| 概率筛选 | `top_p=0.95`、`top_k=20`、`min_p=0` |
| 输出预算 | 官方建议多数问题使用 32768 个输出词元；复杂数学或编程基准可使用 38912。实际设置需同时满足该模型上下文上限和资源预算；缩短时记录为实验设置。 |
| 多轮历史 | 历史助手消息保留最终输出，思考内容按官方模板处理。 |

以上属于推理设置，不能直接作为学习率、训练序列长度或损失范围的默认值。思考内容和最终输出需要在报告中明确区分；触及生成上限时标注截断状态。

来源：[Qwen3-0.6B 官方最佳实践](https://huggingface.co/Qwen/Qwen3-0.6B#best-practices)、[Qwen3-1.7B 官方最佳实践](https://huggingface.co/Qwen/Qwen3-1.7B#best-practices)。

## SFT 样本与损失掩码

带思考的样本应明确提供非空思考段及其后的最终输出。仅更改模板开关，不能给原始解答自动补出有效思考过程。

Qwen 官方训练说明中的 `ignore_empty_think` 用于忽略空思考块的损失；它不等同于屏蔽全部非空思考过程。来源：[Qwen 官方 ms-swift 训练说明](https://github.com/QwenLM/Qwen3/blob/main/docs/source/training/ms_swift.md)。

用户提出的“给定完整思考段，只监督最终输出”目前是待讨论的实验选项，并未被选为默认方案。实现前需要明确思考段来源，以及最终输出指哪些词元。

该选项的含义与限制：

- 保留思考段在输入中的可见性，使用损失掩码排除其直接词元预测损失。训练目标是给定题目和已有思考段后预测最终输出。
- 思考段没有直接词元监督；最终输出损失仍可能通过注意力依赖向思考位置的隐藏状态和共享参数传播梯度。屏蔽损失不等于冻结相关参数或移除计算图。
- 推理时若只有题目，模型需要自行生成思考段。给定参考思考段上的最终输出损失下降，不能证明自行生成的思考过程更好；共享参数更新也不能保证原有思考能力不变。
- 思考词元仍参与前向计算，通常也参与最终输出所依赖的反向传播。标准 Trainer 路径中的标签掩码不能替代显存优化。
- 若思考段由模型离散采样生成，普通最终输出交叉熵不会自动穿过采样决策，对这些思考词元提供策略梯度。使用最终正确性奖励的 GRPO 属于另一类训练目标。

原始 GSM8K 有逐步解答；是否把这些步骤作为思考段监督、只监督最终输出或比较两者，需在下一次样本设计时明确。此文档不替用户选择该实验。

相关语义参考：[PyTorch CrossEntropyLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)、[TRL SFT 损失范围](https://huggingface.co/docs/trl/sft_trainer)、[TRL GRPO 目标](https://huggingface.co/docs/trl/grpo_trainer)。

## 当前实现状态

已有 SFT 与抽样入口仍使用非思考模板，当前 checkpoint 也由此前方案训练。本轮记录后续约定并讨论损失范围；运行配置和样本构造的适配属于后续独立功能小步，不在记录约定时顺带改动。
