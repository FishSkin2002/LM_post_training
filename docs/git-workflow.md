# Git 工作约定

## 身份与语言

新提交使用仓库本地身份 `codex <codex@local.invalid>`；GitHub 认证沿用用户现有账号和 SSH 凭据。提交、合并、回退消息统一使用英文。

## 历史只追加

所有分支都保留已有提交，`codex/` 分支也适用。以新提交表达修改；需要回退时，另建功能分支创建 `revert` 提交，再按下述流程交付。

禁止删除分支或已有提交，禁止重建已有分支、reset 到旧提交、rebase、amend、强制推送及其他替换既有分支历史的操作。新分支使用尚未存在的名称；普通推送保留远程现有提交为祖先。

2026-10-25 的历史重建只依据用户对该次整理的明确授权执行；该次整理结束后，此授权失效，记录不能用作再次改写历史的依据。

## 分支与改动类别

- `codex/…`：Codex 可自主新建分支、切换、开发、正常提交和推送，遵守历史只追加。
- `main`：通过 GitHub 上的 PR 接收改动，本地禁止向其合并或直接推送。
- 其他无前缀分支：可正常合并和推送，遵守历史只追加。
- 其他前缀分支：不切换、修改、合并、推送、重命名或删除。

一项功能的代码、运行配置和直接配套的使用文档属于一类；协作规则、Git 约定及项目目标等项目要求属于独立维护类。规划、进展和发现文件跟随所属任务。

涉及项目要求更新时，先在独立分支完成要求文档并发起 PR，待其按授权在 GitHub 合入主线后，再从最新远程 `main` 新建功能分支。合并后该分支结束开发，后续工作另建新分支。

## 开发完成与合并

代理判断本次功能已完成开发且通过必要验证后，可自主提交、推送并发起以 `main` 为目标的 PR，无须再次询问创建 PR 的许可。同一分支已有 PR 时更新已有 PR，避免重复创建。

`main` 的合入仅在 GitHub PR 中完成。创建 PR 不代表获得合并授权；用户明确要求本次 merge 后，才通过 GitHub 合并该 PR，采用保留提交的 merge commit 方式，并核实远程结果。禁止先在本地合并功能到 `main` 再推送，也不能通过直接推送 `main` 绕过 PR。

其他允许操作的非 `main` 分支之间可直接在本地合并，无须另行索取 merge 授权；分支前缀边界和历史保护仍适用。受控入口只完成本地合并，不自动推送。用户明确要求 merge 时还需正常推送合并结果，保留原有“merge 包含远端交付”的含义。

## 日常 Git 入口

日常写操作使用安装在沙箱受保护目录的固定入口：

```text
/usr/bin/python3 -I -S /mnt/c/Users/yunli/.codex/bin/qwen-git-workflow.py <动作>
```

| 动作 | 参数及效果 |
| --- | --- |
| `start codex/<新名称>` | 获取最新远程 main，从 origin/main 创建尚未存在的功能分支，不修改本地 main。 |
| `switch <分支>` | 切换到允许操作的已有分支。 |
| `commit -m "English message"` | 在 codex/ 分支创建普通提交。 |
| `push <非 main 分支>` | 检查远程提交是本地提交的祖先后普通推送到 origin 同名分支，拒绝直接推送 main。 |
| `fetch` | 获取 main，只在前进或初次创建时更新 origin/main。 |
| `merge <允许操作的分支>` | 在当前非 main 分支创建普通合并，不自动推送；main 作为目标时拒绝执行。 |
| `revert <提交哈希>` | 在 codex/ 分支创建新的回退提交。 |

暂存使用 `git -C /home/yunli/code/qwen/codex add -- <明确文件>`，检查状态、日志和差异可直接使用只读 Git 命令。

入口固定仓库和 origin，不转发任意 Git 参数；删除、强推、amend、reset、rebase 等动作或参数会被拒绝。发生冲突或未完成的 Git 操作时停止并检查状态，保留已有历史。

源文件是 [Git 入口](../tools/git_workflow.py)，验证见 [隔离仓库测试](../tools/test_git_workflow.py)。更新入口或授权文件时，先检查差异、运行验证，再通过正式宿主审批安装；不为原始 Git 写命令申请宽泛持久允许。

## 授权文件

[项目授权源文件](codex-git.rules) 对应用户规则层的 `qwen-codex-workflow.rules`。直接 Git 写命令的过宽允许，包括 `default.rules` 中的重复项，需要一并清理；入口安装命令也不保留为长期免审批授权。

Codex 启动时读取规则；修改磁盘文件不代表当前会话已重新加载。该方案约束日常 Git 命令入口，不能把 AGENTS.md 或一般代码执行权限描述为对所有进程的系统级隔离。其他程序同样不得绕过本约定改写 Git 历史。

参考：[OpenAI 官方命令规则说明](https://learn.chatgpt.com/docs/agent-configuration/rules)。
