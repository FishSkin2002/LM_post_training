# 大模型算法实习项目规划

## 总体目标

在 2027 年春季开学前，围绕大模型后训练和 Agent 算法准备实习。

项目组合：

- 项目一：数学推理后训练，侧重模型训练与算法实验。
- 项目二：中小学数学教学 Agent，侧重课程知识检索、解题约束和教学效果优化。

两个项目共享数学领域知识，但解决不同的问题。

# 项目一：小模型数学推理后训练

## 1. 项目目标

基于 Qwen3-4B-Instruct-2507 和公开数学数据，实践 SFT、DPO 与 GRPO，研究各阶段对模型数学推理能力的影响。

## 2. 技术路线

基础模型：Qwen/Qwen3-4B-Instruct-2507，使用其原生聊天模板；模型选择与样本格式见[模型与样本约定](qwen3-base.md)。

数据集：SFT 使用 OpenR1-Math-220k 的 R1 解答，DPO 使用 `tasksource/prm800k_dpo` 的完整解答偏好对，GRPO 使用 Skywork-OR1-RL-Data 的数学题。保留 GSM8K 读取接口供测试等用途。

训练框架：PyTorch、Transformers、TRL。

训练方法：

1. 对未经本项目训练的同一官方 Instruct 模型做基线评测。
2. 使用数学题及筛选后的 R1 完整解答进行 SFT，system 放固定任务和 boxed 格式要求，user 保留原题。
3. 从同一 SFT 模型分别开展 DPO 和 GRPO，采用[各自的数据、目标与运行约定](post-training-workflow.md)。
4. 使用同一批 SFT 验证题统一评测原始模型、SFT 模型、DPO 模型和 GRPO 模型。

## 3. 核心实验问题

- SFT 是否改善模型的数学题准确率？
- DPO 和 GRPO 各自能否在 SFT 基础上进一步改善表现？
- 奖励变化与实际准确率是否一致？
- 奖励设计或采样参数变化会如何影响训练结果？

先完成基础实验，再根据结果选择一项值得深入的消融实验。

## 4. 项目成果

形成一套可复现的数学推理后训练流程，包含训练代码、实验配置、评测结果、关键曲线、失败案例与技术报告。

项目重点是理解算法、验证实验结论，而不是追求模型规模或预设性能提升。

# 项目二：中小学数学教学 Agent

## 1. 项目目标

研究如何利用教材内容、课程知识点和前置知识关系，让大模型不仅能解出数学题，还能使用符合指定年级要求的方法进行讲解。

## 2. 技术路线

优先调查和利用公开资源：

- CMATH：中文小学数学题。
- FineMath：细粒度小学数学评测。
- CMM-Math：中文中小学数学推理。
- K12-KGraph：课程知识图谱与相关评测资源。

根据资源的实际质量、许可和适用性，选择合适的数据，不从零构建大规模题库。

第一版选定一个年级范围或知识主题，围绕教材检索、知识点定位、解题过程生成和教学提示开展实验。

## 3. 核心实验问题

比较以下方案：

1. 基础模型直接解题。
2. 检索相关教材内容后解题。
3. 利用课程知识及前置关系引导检索和解题。

主要评估：

- 最终答案正确率。
- 知识点选择是否合理。
- 解法是否符合指定年级的知识范围。
- 教材引用是否支持回答。
- 教学提示是否清晰、适合学生理解。

## 4. 项目成果

形成一个可运行的教学 Agent，以及公开数据资源说明、检索与回答流程、对照实验、错误分析和技术报告。

项目重点是验证课程知识约束是否改善教学效果，而不是堆叠 Agent 框架或复杂功能。

# 两个项目的关系

项目一研究：如何通过后训练改善模型的解题能力。

项目二研究：如何通过课程知识和检索机制，让模型以符合教学要求的方式解决和讲解问题。

先积累项目一的训练与评测经验，再开展项目二。具体实现顺序和开发方式由我根据实际情况安排。

最终目标是通过两个项目展示后训练算法能力、实验分析能力，以及对 Agent 效果优化的理解。
