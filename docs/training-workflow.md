# 训练运行约定

用户于 2026-10-28 确定以下训练、验证、续训、加训及独立生成评测行为。最新决定为：训练过程中只验证 loss，生成指标通过独立脚本计算，并在正常训练结束后自动执行一次全量生成评测；该决定替代此前的训练中定期生成及开关方案。模型、样本及损失保持 [Base 训练约定](qwen3-base.md)。

## 数据与验证

- 从 GSM8K train 固定划出 10% 验证样本，seed=42；test 留作最终评测。训练样本和验证样本互不重叠，验证样本不参与参数更新。
- 保存本次数据划分及来源信息；断点续训和后续加训沿用同一划分，并校验数据一致。不把已参与训练的样本重新当成独立验证数据，缺少划分信息时不静默重建来源。
- 训练过程中的验证只在完整验证集上计算 loss，不生成答案或计算生成正确率。不配置训练中生成频率、跳过计数或生成开关。

## 独立生成评测

- 提供独立脚本 `evaluate_checkpoint.py`，通过必填 `--checkpoint` 指定当前 Base LoRA 流程保存的 `checkpoint-*` 或 `final/`，方便手动比较训练中的多个断点及最终模型。评测不创建优化器，不更新权重或训练步数，也不调用续训入口。
- 读取来源保存的运行信息并校验数据一致，沿用其固定验证划分。缺少来源或划分信息时明确报错，不静默重新划分。test 仍保留作最终独立评估，不用作训练过程中手动比较 checkpoint 的默认集合。
- 可选 `--num-samples` 指定题数；省略时评测完整验证集。题数必须是正整数且不超过验证集大小，越界明确报错。同一题数总是选择验证集固定顺序的前 N 题，以便不同 checkpoint 使用相同题目。
- 沿用贪心解码、1024-token 上限；使用 [Base 训练约定](qwen3-base.md) 中的普通文本提示，输入止于 Answer 前缀，不含参考解答，输出原生 EOS 时停止。手动和训练结束自动调用共享相同的生成、计分和报告实现。
- 输出生成正确率、格式有效率、截断率、实际题数、耗时和吞吐；结果保存为独立评测报告，记录模型来源、数据划分、实际题目索引及生成/计分设置。报告路径可显式指定，不改变来源 checkpoint 的训练状态。
- 正常训练结束后，先完整保存 `final/` 和训练状态，再自动执行一次完整验证集的生成评测。自动评测使用最终权重，复用训练进程已有模型，避免同时加载第二份权重；不把最后一步训练验证重新变成生成评测。
- 手动中断不触发训练结束评测。评测失败或中断不影响已经保存的训练结果，可随后针对保存好的 `final/` 单独重跑评测，无需加训。

### 逐题保存与自动续跑

用户于 2026-10-29 确定：每生成完一道题立即追加保存，重启同一次评测时检查已有记录并接着生成。手动评测和训练结束后的自动评测共用此行为，不新增续跑开关。

- 保留最终汇总 JSON；在同目录以相同基础文件名保存 `.progress.jsonl` 进度日志。例如 `evaluations/checkpoint-1000-n32.json` 对应 `evaluations/checkpoint-1000-n32.progress.jsonl`；自定义 `--output` 时按同样规则确定进度文件。
- 每个完整回答对应一行 JSON，保留题目索引、问题原文（question）、完整标准解答（reference_answer）、模型生成文本（answer）、token 数、判分结果、截断状态和该题耗时。标准解答使用与训练/验证相同的去计算器注释版本，保留完整推导及 #### 最终答案，不只保存最后数值；问题与标准解答也随逐题记录进入最终汇总 JSON。生成输入仍不包含标准解答。生成一题便以追加模式写入并刷新文件，再继续下一题；文件只存逐题记录，不增加任务头。错误、格式无效或截断的回答同样作为已完成记录保存。
- 重复运行相同 checkpoint、题数和输出路径的命令时，读取已有记录数 N，直接跳过固定顺序的前 N 题，从第 N+1 题继续追加。保留当前来源及数据划分校验，不为进度文件新增权重摘要、任务签名、逐题顺序核验或恢复状态管理。
- 启动时用英文显示已完成数和总题数，进度条从 N 开始。单题生成中途被中断时，没有完整记录的当前题在下次重算；不恢复 token 或 KV cache，不增加日志修复逻辑。
- 完成后用旧记录与新增记录一起汇总原有指标，并保存最终 JSON，保留逐题日志；已经全部完成时不重复生成。生成耗时累加记录中的题目耗时，吞吐按全部题数计算，不计停机间隔。需要从头重评时使用新的 `--output` 路径，不新增命令行开关。

## 生成答案判定

- 主指标为项目验证集生成正确率，采用严格格式、数值匹配。生成文本应恰有一个 ####，其后除空白外只有一个完整有限十进制数。
- 支持负号、合法千分位逗号和小数，使用精确数值归一化比较；例如 5.0 与 5 相等，不使用浮点近似。缺标记、多标记、额外尾部文字或非法数字均为格式不合格。
- 格式不合格或生成被截断均计为错误。正确率分母为全部评测题目，不只计算能解析的回答；不回退提取推导末尾的数字。
- 同时记录格式有效率与生成截断率，便于区分格式、预算和数值错误。此判定是项目协议，不直接等同公开榜单的提示、提取与计分协议。
- 比较原始 Base 与 SFT 的生成结果时，统一使用 [Base 训练约定](qwen3-base.md) 中的说明和 Question/Answer 前缀，并保持题目与解码设置一致。提示只要求最终答案格式；不提取或验算公式，也不因缺少计算器注释而判错。未遵循 #### 答案格式仍按既定规则计错并单独体现在答案格式有效率中。

## 记录与保存

- 每 500 个优化器更新步验证并保存 checkpoint，训练标量每 10 步记录，保留最近两个 checkpoint；正常训练结束包含最后一步验证和保存。频率由基础配置直接指定，不自动调参或自动选最佳 checkpoint。
- TensorBoard 记录训练 loss、裁剪前梯度范数、学习率、epoch；横轴为 global_step。训练 loss 是日志区间平均值，梯度范数是记录步的值。
- 训练阶段的验证记录 loss 及其耗时/吞吐。生成指标单独写入评测报告，明确实际题数；未执行的生成不记录成正确率 0。验证 loss 不等于生成答案正确率。
- 每次训练运行使用固定的 TensorBoard 目录。断点续训沿用该目录和步数，从较早断点恢复时排除断点之后失效的旧事件；加训另建记录。
- 沿用 Transformers Trainer、原生 TensorBoardCallback 与 PEFT，加入必要的 TensorBoard 依赖；不恢复额外显存优化或引入新训练框架。

## 英文终端展示

- 项目产生的终端提示、标题、进度条说明和指标摘要统一使用英文。训练、验证 loss、训练集/验证集分词、独立生成评测及抽样生成的进度条均在左侧标明阶段；保留耗时、已完成数量及可用的剩余时间信息。
- 指标以易读的 `key=value` 行显示，去除字典形式的引号和大括号，例如 `Training | loss=0.3908 | grad_norm=2.564 | learning_rate=9.505e-05 | epoch=0.1487`。
- 只格式化终端展示副本，保留传给 TensorBoard 和结果文件的原始数值；原始题目/解答保持原文。README 和问答报告继续使用现有语言。

## 三种训练用途

| 用途 | 起点与状态 | 轮次、目录与记录 |
| --- | --- | --- |
| 新训练 | 原始 Qwen3 Base，新建 LoRA 与优化器等状态 | 按配置训练；新目录、新 TensorBoard run。 |
| 断点续训 | 完整 checkpoint，恢复适配器、优化器、调度器、随机状态和 Trainer 进度 | 接着原计划训练；默认回到 checkpoint 所属运行目录，延续日志，不加数字后缀。 |
| 完成后加训 | 加载现有适配器并开启新阶段；优化器、调度器、global_step 和 epoch 重新开始 | 追加轮次仅指新阶段再训练几轮；新目录、新 TensorBoard run，记录来源。 |

- 三种用途的来源参数互斥。加训不叠加第二套适配器；结构取自来源，学习率按显式配置使用，不自动调整。
- 续训在加载权重前校验完整状态、Base、LoRA 参数、普通文本提示、去注释规则及结束设置、数据划分与训练计划，缺少必要状态则明确报错。final 仅作适配器权重来源，不能作为完整断点恢复。
- 当前普通文本格式下同 Base、同训练计划的完整断点可继续恢复。旧聊天格式不属于当前来源范围，不提供加载、恢复、加训或评测的兼容路径。
- 已完成训练使用加训入口；改变原计划的总轮次不冒充原状态的完整恢复。加训阶段也可从自己的 checkpoint 恢复。
- 新训练及加训原子创建输出目录，冲突时依次尝试原名、-1、-2；同名空目录或文件也视为已占用。显式输出路径遵循同样规则，实际目录用于所有产物和日志。
- Ctrl+C 后从最近已保存的完整 checkpoint 恢复；本轮不新增中断时自动保存功能，不承诺恢复尚未写入磁盘的工作。

## 验收

使用临时随机微型模型核对：中断恢复与连续训练一致、缺状态拒绝、固定划分和评测题目复现、训练/验证 TensorBoard 标量及步数、目录避重，以及加训只继承权重且重置训练状态。

新增核对：训练中的验证不调用生成；训练正常结束在保存后只评测一次全量；中断不启动结束评测；手动评测 checkpoint/final 及题数选择正确，且不更新训练权重/状态；评测失败后保存结果可独立重评；英文进度和非字典日志不改变原始数值。恢复已保存断点与未保存工作的损失分别说明。

普通文本格式核对：四个脚本共用精确提示前缀；清理后的 answer 与一个 EOS 接受监督，前缀与 padding 被掩码；EOS 与 PAD 共用 ID 时，真实结束标签仍参与损失；生成输入不含参考答案，能在原生 EOS 停止并正确识别截断。对完整训练集检查去注释不改变最终答案、推导的非注释部分与无注释样本，不残留注释边界；不添加公式评分。新来源不依赖聊天模板文件；旧格式来源在加载权重前拒绝；当前格式的恢复、加训及报告保存保持有效。

逐题保存与续跑核对：模拟首题落盘后中断，确认重启按已有记录数只生成剩余题，已有记录不被覆盖；正确、错误、格式无效与截断记录都可复用，汇总分母覆盖全部题。检查JSONL及最终JSON中的问题原文、清理后的完整标准解答与模型回答可直接对照，标准解答不进入生成输入。检查完成后重跑不重复生成，自动结束评测使用同一路径，训练产物及训练状态不受影响。不为额外校验或日志修复扩展本次范围。
