# 训练运行约定

用户于 2026-10-28 确定以下训练、验证、续训和加训行为。模型、样本及损失保持 [Base 训练约定](qwen3-base.md)。

## 数据与验证

- 从 GSM8K train 固定划出 10% 验证样本，seed=42；test 留作最终评测。训练样本和验证样本互不重叠，验证样本不参与参数更新。
- 保存本次数据划分及来源信息；断点续训和后续加训沿用同一划分，并校验数据一致。不把已参与训练的样本重新当成独立验证数据，缺少划分信息时不静默重建来源。
- 验证 loss 在完整验证集上计算。定期验证从验证集固定选择同样的 128 条生成答案；正常训练结束生成完整验证集。
- 生成沿用贪心解码和 1024-token 上限，输入仅含题目。全量结果与固定子集结果分别标识并记录题数，保持不同分母下结果的含义明确。

## 生成答案判定

- 主指标为项目验证集生成正确率，采用严格格式、数值匹配。生成文本应恰有一个 ####，其后除空白外只有一个完整有限十进制数。
- 支持负号、合法千分位逗号和小数，使用精确数值归一化比较；例如 5.0 与 5 相等，不使用浮点近似。缺标记、多标记、额外尾部文字或非法数字均为格式不合格。
- 格式不合格或生成被截断均计为错误。正确率分母为全部评测题目，不只计算能解析的回答；不回退提取推导末尾的数字。
- 同时记录格式有效率与生成截断率，便于区分格式、预算和数值错误。此判定是项目协议，不直接等同公开榜单的提示、提取与计分协议。

## 记录与保存

- 每 500 个优化器更新步验证并保存 checkpoint，训练标量每 10 步记录，保留最近两个 checkpoint；正常训练结束包含最后一步验证和保存。频率由基础配置直接指定，不自动调参或自动选最佳 checkpoint。
- TensorBoard 记录训练 loss、裁剪前梯度范数、学习率、epoch；横轴为 global_step。训练 loss 是日志区间平均值，梯度范数是记录步的值。
- 验证记录 loss、生成正确率、格式有效率、截断率、实际题数与耗时/吞吐；完整验证集和固定生成子集结果分开标识。验证 loss 不等于生成答案正确率。
- 每次训练运行使用固定的 TensorBoard 目录。断点续训沿用该目录和步数，从较早断点恢复时排除断点之后失效的旧事件；加训另建记录。
- 沿用 Transformers Trainer、原生 TensorBoardCallback 与 PEFT，加入必要的 TensorBoard 依赖；不恢复额外显存优化或引入新训练框架。

## 三种训练用途

| 用途 | 起点与状态 | 轮次、目录与记录 |
| --- | --- | --- |
| 新训练 | 原始 Qwen3 Base，新建 LoRA 与优化器等状态 | 按配置训练；新目录、新 TensorBoard run。 |
| 断点续训 | 完整 checkpoint，恢复适配器、优化器、调度器、随机状态和 Trainer 进度 | 接着原计划训练；默认回到 checkpoint 所属运行目录，延续日志，不加数字后缀。 |
| 完成后加训 | 加载现有适配器并开启新阶段；优化器、调度器、global_step 和 epoch 重新开始 | 追加轮次仅指新阶段再训练几轮；新目录、新 TensorBoard run，记录来源。 |

- 三种用途的来源参数互斥。加训不叠加第二套适配器；结构取自来源，学习率按显式配置使用，不自动调整。
- 续训在加载权重前校验完整状态、Base、LoRA 参数、数据划分与训练计划，缺少必要状态则明确报错。final 仅作适配器权重来源，不能作为完整断点恢复。
- 已完成训练使用加训入口；改变原计划的总轮次不冒充原状态的完整恢复。加训阶段也可从自己的 checkpoint 恢复。
- 新训练及加训原子创建输出目录，冲突时依次尝试原名、-1、-2；同名空目录或文件也视为已占用。显式输出路径遵循同样规则，实际目录用于所有产物和日志。

## 验收

使用临时随机微型模型核对：中断恢复与连续训练一致、缺状态拒绝、数据划分和生成子集复现、训练/验证 TensorBoard 标量及步数、目录避重，以及加训只继承权重且重置训练状态。恢复已保存断点与进程中断导致尚未保存的工作损失分别说明，不承诺恢复未写入磁盘的状态。
