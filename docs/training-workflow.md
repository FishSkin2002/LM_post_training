# 训练运行约定

用户于 2026-10-29 确定以 Qwen3-4B-Instruct-2507、OpenR1 R1 解答和原生聊天模板开展训练前后对比。模型、数据目标、system/user/assistant 分工及优化以[模型与样本约定](qwen3-base.md)为准。训练中仍只验证 loss，正常结束保存后自动执行一次全量验证集生成评测。

## 数据与验证

- 主数据使用 OpenR1-Math-220k default/train，先按 problem 原文分组，同题只属于一个划分。对符合当前来源、轨迹和长度规则的题目组，以 seed=42 固定划出 10% 验证集，其余训练；一题只取一条选定轨迹。参考答案不可解析、无合格轨迹及超长等筛除原因在数据准备阶段单独统计，不在生成后改变分母。
- 记录数据仓库、config、split、revision/fingerprint、筛选与轨迹选择规则、组/记录/轨迹索引及最终划分。断点续训与加训沿用保存的同一计划并校验来源；缺失时明确报错，不把已训练题目重新划为验证集。
- 保留 GSM8K 读取和原有 seed=42、10% 划分能力，供后续测试；其 test 继续保留作最终独立评估。接口和报告明确数据源，不把不同来源的题数、划分或终值字段混为一谈，也不宣称跨数据集已经完全去重或排除污染。
- 数据准备和训练采用同一套模型分词、长度规则和最终划分；统计完整渲染长度，超长解答筛除而不截断。训练与生成预算分别显式配置并记录，在正式比较前依据长度检查确定，同次训练前后比较固定不变。
- 训练中的验证只在完整保留验证集上计算 loss，不调用生成或生成评分，不增加训练中生成频率/开关。

## 独立生成评测

- 提供独立脚本 `evaluate_checkpoint.py`，来源互斥：`--checkpoint` 指定当前流程的 checkpoint-* 或 final/；`--model-name` 指定尚未接受本项目训练的 `Qwen/Qwen3-4B-Instruct-2507`。缺少或同时指定来源明确报错；评测不创建优化器、不更新权重或训练状态。
- checkpoint 来源读取运行信息、划分和实际模板并校验。原始 Instruct 不要求已有训练目录或 LoRA，直接加载同一官方模型和分词器；使用与 SFT 相同的数据选择、分词/长度与划分逻辑，同题数下题目索引和顺序一致。已训练产物的来源缺失时不静默重建。
- 两种来源使用一致的底座精度、原生模板、固定 system、题目原文、解码和评分。原生 EOS 为 im_end；不提供参考解答或终值，不预填 think。仅缓存加载行为保持，不在评测入口隐式下载权重。
- `--num-samples` 仍可选，省略时评测完整验证集；必须为不超过验证集大小的正整数。相同题数选择固定顺序前 N 题。
- 初始解码保持贪心，生成上限改为显式记录的预算，而非无说明沿用旧 1024 常量。训练前后用相同参数与上限；输出正常 EOS 或截断状态，不把缺思考段判为错误。
- 输出最终答案正确率、格式有效率、截断率、实际题数、生成耗时及吞吐；逐题保留实际生成 token 数，便于判断长度和成本变化。报告记录原始模型/LoRA 来源、模型名、checkpoint（如有）、数据身份、实际索引、提示/模板及精度、生成与评分设置。
- checkpoint 默认仍在运行的 evaluations/ 中保存；原始模型默认使用 outputs/evaluations/ 下包含 original、模型短名、数据身份和题数的文件名，避免复用旧 Base/GSM8K 结果。数据身份也进入 checkpoint 报告的默认文件名。`--output` 继续可指定路径，同名基础名生成 JSON、progress.jsonl 和 Markdown。
- 正常训练结束先完整保存 final/ 和状态，再自动执行一次完整验证集生成评测。复用训练进程已有模型，避免同时加载第二份权重；生成缓存设置与训练关闭 KV cache 分开处理，完成后保持训练/保存配置正确。
- 手动中断不触发结束评测；评测失败不影响已保存训练结果，可随后独立评测 final/，无需加训。

### 逐题保存与按条数续跑

- 保留最终 JSON、每题一行的 `.progress.jsonl` 和同名 `.md` 阅读版。每个完整回答生成后立即追加 JSONL 并 flush，再更新 Markdown；启动可用已有 JSONL 重建阅读版。
- 记录题目和轨迹索引、question 原文、reference_answer 完整选定监督解答、reference_final_answer 独立参考终值、answer 生成文本、token 数、判分/格式/截断状态及题目耗时。完整标准解答与最后终值保持分开，均不进入生成输入；逐题内容进入最终汇总。
- 相同来源、数据、题数和输出路径再次运行时，按已有完整记录数 N 直接跳过前 N 题，从第 N+1 题追加。正确、错误、格式无效和截断记录都复用；不增加任务头、摘要、任务签名、逐题顺序核验或日志修复。
- 英文展示已完成数和总数，进度条从 N 开始；单题中途中断，下次重算尚无完整记录的这一题，不恢复 token/KV cache。
- 汇总旧记录与新增记录，分母覆盖全部题目；耗时累加逐题生成耗时，不计停机间隔。完整评测再跑不重复生成；从头重评使用新 output，不新增续跑开关。

## 生成答案判定

- 对 OpenR1 使用独立 answer 作参考终值；若评测 GSM8K，从原答案 #### 后提取参考数值。先在准备阶段核实参考可解析，证明题、缺失终值或当前解析器不支持的参考不进入本轮可验证集合，数量和原因明确记录。
- 模型生成必须有完整且非空的 `\boxed{...}` 最终答案。使用解答末个 boxed 块，正确处理嵌套花括号；不能用简单的首个右花括号截断分数，也不回退扫描推导中的最后一个数字。多个中间 boxed 本身不判错；末个未闭合或不可解析则格式无效。
- 对提取的 boxed 内容和参考终值采用 Math-Verify 的数学表达式解析/等价判定，显式固定解析器版本及配置；选项型参考需要明确的字符串解析配置。支持范围由实际解析器决定，不宣称任意自然语言数学对象都可验证，不调用 LLM 评分或执行解题代码。
- 分数与小数等价如 `1/4` 和 `0.25` 可判为正确；这不改变 SFT 的词元交叉熵。只比较最后结果，不验证思考或推导中的每一步。
- 格式无效、无法判定或生成被截断均计为错误；正确率分母为全部预先确定的评测题。记录格式有效率与截断率，不能通过丢弃失败回答提高正确率。本协议不直接等同公开榜单协议。
- 比较原始 Instruct、SFT 和未来 GRPO 时固定模型起点、system/user、模板、题目、精度和解码预算；生成更多思考文本本身不算正确率提升。

## 记录与保存

- 每 500 个优化器更新步验证并保存 checkpoint，训练标量每 10 步记录，保留最近两个 checkpoint；正常训练结束包含最后一步验证和保存。频率由基础配置直接指定，不自动调参或自动选最佳 checkpoint。
- TensorBoard 记录训练 loss、裁剪前梯度范数、学习率、epoch；横轴为 global_step。训练 loss 是日志区间平均值，梯度范数是记录步的值。
- 训练阶段的验证记录 loss 及其耗时/吞吐。生成指标单独写入评测报告，明确实际题数；未执行的生成不记录成正确率 0。验证 loss 不等于生成答案正确率。
- 每次训练运行使用固定的 TensorBoard 目录。断点续训沿用该目录和步数，从较早断点恢复时排除断点之后失效的旧事件；加训另建记录。
- 沿用 Transformers Trainer、原生 TensorBoardCallback 与 PEFT，加入必要的 TensorBoard 依赖；仅采用[模型与样本约定](qwen3-base.md)中已确认的两项优化，不引入新训练框架。

## 英文终端展示

- 项目产生的终端提示、标题、进度条说明和指标摘要统一使用英文。训练、验证 loss、训练集/验证集分词、独立生成评测及抽样生成的进度条均在左侧标明阶段；保留耗时、已完成数量及可用的剩余时间信息。
- 指标以易读的 `key=value` 行显示，去除字典形式的引号和大括号，例如 `Training | loss=0.3908 | grad_norm=2.564 | learning_rate=9.505e-05 | epoch=0.1487`。
- 只格式化终端展示副本，保留传给 TensorBoard 和结果文件的原始数值；原始题目/解答保持原文。README 和问答报告继续使用现有语言。

## 三种训练用途

| 用途 | 起点与状态 | 轮次、目录与记录 |
| --- | --- | --- |
| 新训练 | 原始 Qwen3-4B-Instruct-2507，新建 LoRA 与优化器等状态 | 按配置训练；新目录、新 TensorBoard run。 |
| 断点续训 | 完整 checkpoint，恢复适配器、优化器、调度器、随机状态和 Trainer 进度 | 接着原计划训练；默认回到 checkpoint 所属运行目录，延续日志，不加数字后缀。 |
| 完成后加训 | 加载现有适配器并开启新阶段；优化器、调度器、global_step 和 epoch 重新开始 | 追加轮次仅指新阶段再训练几轮；新目录、新 TensorBoard run，记录来源。 |

- 三种用途的来源参数互斥。加训不叠加第二套适配器；结构取自来源，学习率按显式配置使用，不自动调整。
- 续训在加载权重前校验完整状态、底座模型、LoRA 参数、原生模板、system 与数据处理、精度及结束设置、数据划分与训练计划，缺少必要状态则明确报错。final 仅作适配器权重来源，不能作为完整断点恢复。
- 当前 Instruct 聊天协议下，同底座、同模板、同数据与训练计划的完整断点可继续恢复。旧 Base 普通文本及更早聊天产物保留作历史资料，不进入新版恢复、加训或评测路径。
- 已完成训练使用加训入口；改变原计划的总轮次不冒充原状态的完整恢复。加训阶段也可从自己的 checkpoint 恢复。
- 新训练及加训原子创建输出目录，冲突时依次尝试原名、-1、-2；同名空目录或文件也视为已占用。显式输出路径遵循同样规则，实际目录用于所有产物和日志。
- Ctrl+C 后从最近已保存的完整 checkpoint 恢复；本轮不新增中断时自动保存功能，不承诺恢复尚未写入磁盘的工作。

## 验收

使用临时随机微型模型核对以下行为，不下载真实权重或启动真实训练：

- system 内容精确、user 保持题目原文、assistant 保留 R1 的 LaTeX/think；训练与生成前缀分词对齐。提示/角色头/padding 被掩码，R1 正文与一个原生 im_end EOS 受监督；不重复特殊词元、不预填思考或泄露参考答案。
- OpenR1 正确性/完整性字段对齐和确定性单轨迹选择、无合格轨迹的筛除、完整渲染长度筛除及计数；同题组不会跨训练/验证，训练前模型与 SFT 使用相同最终题目和顺序。保留 GSM8K 读取及终值提取，不以源数据记录数冒充独立题数。
- boxed 嵌套花括号、多个中间结果、缺失/未闭合/不可解析终值及截断；分数/小数、负数与适用符号的等价判断。参考不支持在准备时明确报告，生成失败不改变分母；不把最终答案通过当过程验证。
- 同一来源的中断恢复与连续训练一致，缺状态或模型/数据/模板/精度不符时在加载前拒绝；加训只继承权重，重置优化器与阶段步数。旧 Base 普通文本产物保留且拒绝混用，目录避重和 TensorBoard 步数/事件处理保持。
- 训练中验证不调用生成；正常结束保存后仅全量生成评测一次，中断不触发；手动评测互斥来源和题数校验，不创建适配器或更新权重。原始模型默认/自定义输出、JSONL/Markdown/JSON，以及 checkpoint 和自动评测使用同一实现。
- 首题 flush 后中断、按 N 条只补剩余题、错误/格式无效/截断复用、完成重跑不生成、Markdown 丢失重建、汇总失败重建；不额外扩展进度签名或修复。
- BF16 底座和 FP32 LoRA 参数设置、非重入检查点下的梯度与参数更新、训练关闭/生成恢复缓存和统一评测精度。在目标 GPU 上核验支持条件后才启动正式训练；CPU/随机微型接口检查不冒充真实显存或吞吐测量。
