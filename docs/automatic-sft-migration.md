# vLLM 主环境与旧 SFT 自动迁移

用户于 2026-11-06 确认：后续主线统一采用支持 vLLM 的环境，名称由用户自定；旧 SFT 迁移应从仅有主环境的机器启动，自动配好兼容环境、处理数据并供后续命令复用。系统只需保留一套支持 CUDA 12.8 的驱动；不要求另装系统级 CUDA Toolkit 12.4。本文规定新增目标，按[Git 工作约定](git-workflow.md)先交付要求，再实现功能。

## 主环境与依赖入口

- 主环境负责后续新 SFT、DPO、GRPO、抽样和生成评测。默认依赖入口以已选的 vLLM 配套组合为准，旧训练依赖单独保留作历史兼容资料，不再让默认安装指向旧栈。
- 根目录 `requirements.txt` 是主环境唯一的正常安装入口，直接提供 vLLM 配套依赖。旧依赖、兼容配置及旧数据处理子进程入口集中到 `legacy/sft_data/`，只供迁移程序调用；README 不再要求用户进入该目录安装或执行文件，不保留让用户选择两套主依赖文件的流程。
- 环境名称不参与功能判断；`qwen-vllm` 只能作为文档示例。普通脚本使用当前 Python，检查有效依赖、设备和精度；训练结束评测继续使用同一个 Python。
- 系统驱动与 Python 包的 CUDA 运行库分开说明。主环境使用已选的 CUDA 12.8 构建及其配套依赖；系统可只安装 Toolkit 12.8，不把安装 Toolkit 当成驱动或 Python 依赖已经满足。

## 从只有主环境开始迁移

- 提供独立迁移入口，用户在主环境指定旧 SFT `final/` 即可开始。不要求预先存在旧 Conda 环境，不要求手动 `activate`、逐个安装旧包或反复切换环境。
- 迁移入口定位已有 Conda，可显式指定 Conda 可执行文件；找不到时明确提示安装或指定 Conda。无需绑定主环境、base 或兼容环境的名称及用户主目录。
- 程序在自己管理的位置通过 Conda 创建独立 Python/pip 环境，再用 pip 安装版本固定的旧数据处理依赖。仅采用当前项目已支持的旧 SFT 兼容配置，不声称能够凭空恢复任意历史环境。
- 优先使用 CPU 版 PyTorch。兼容环境只读取、筛选、分词和核对数据，不加载模型权重进行训练或生成，不依赖 GPU，也不要求安装另一版系统 CUDA Toolkit。
- 用兼容环境的 Python 子进程执行准备数据；子进程不修改主环境、不要求用户激活环境，也不再次递归发起迁移。原有环境和训练进程不作为执行前提。
- 对外只提供主环境中的迁移入口；兼容目录的具体 Python 与依赖文件由该入口定位。主环境读取迁移结果的公共逻辑与旧环境专用执行逻辑分开，避免普通脚本误导入兼容环境的依赖。
- 配置与创建过程使用明确的 Conda 渠道和 pip 安装来源；不自动接受新增服务条款。首次安装需要可用网络或相应包缓存、写入权限及足够磁盘空间。

## 原数据核对与迁移结果

- 从 SFT 产物恢复原模型、分词器、提示、长度预算、数据来源和保存的划分，按对应旧数据处理方式准备数据。只接受与原 SFT 运行记录一致的结果，再写出可供主环境读取的准备数据及身份清单。
- 保留原题、监督解答、参考终值、样本与题目组顺序、原始索引及训练/验证划分；不重新挑题、不修改答案语义、不覆盖原 SFT 权重或运行记录。
- 原始数据需要从可用缓存或所记录的数据来源取得。原依赖配置无法重建、原始数据不可得或结果与 SFT 记录不一致时明确失败，不通过忽略指纹、强行套用索引或换一批题来完成迁移。
- 输出保留经核对的原数据身份，主环境继续执行既有来源与划分校验。兼容读取旧分词器元数据时，保持实际词表、提示 token 和聊天协议一致。

## 复用与恢复

- 兼容环境由程序管理并可复用，不覆盖用户现有环境。区分创建中、安装中和已可用状态；只有依赖检查成功才标记可用。避免并发重复创建，失败或中断后的再次运行能明确恢复或报出处理方式。
- 迁移输出区分准备中与完成；仅当数据核对和保存成功才发布完成结果。失败产物不作为有效缓存，原 SFT 产物始终保留。
- 迁移完成后，普通命令可以从源 SFT 运行定位该缓存，不要求每次填写数据导出路径。DPO/GRPO 的评测仍追溯到其源 SFT；原始模型对照在指定同一 SFT 来源时复用同一批验证题。
- 保留显式指定已准备数据的能力。后续命令记录有效来源路径；已有有效缓存时不再次创建兼容环境或调用旧解释器。
- 日常评测和训练不因缺少缓存而静默联网安装旧环境；应明确引导运行一次迁移入口。新 SFT 在主环境生成的产物按正常流程工作，无需执行旧产物迁移。
- 生成评测的历史 JSONL/Markdown 仍只按已保存条数续跑与追加，不因迁移增加历史判分核查或重写。

## 验收与交付

- 用随机微型 SFT 产物验证仅有主环境、无兼容环境前缀的首次迁移：自动 Conda 创建、pip 安装、CPU 准备、原划分核对和缓存发布全部走通。验收不借用开发机已有旧环境冒充自动重建成功。
- 验证兼容环境确为 CPU 版，不依赖系统 Toolkit 12.4；实际依赖版本与所用兼容配置一起记录。环境名称改变不影响主流程。
- 验证主环境读取迁移结果后，词表与提示 IDs、题目/监督文本、原始索引和训练/验证划分保持一致，普通评测和后续阶段能够自动复用。
- 针对性验证已有缓存复用、并发与中断恢复，以及缺少 Conda、安装失败、原数据不一致和不完整缓存；失败不修改 SFT 产物，不将半成品标为成功。
- 功能文档给出主环境安装、一次迁移和日常使用的完整命令。区分模拟子进程检查与真实自动建环境验证，不启动真实大模型训练或 API 判分。

## 依据

- [PyTorch 历史安装说明](https://docs.pytorch.org/get-started/previous-versions/)提供旧版本 CPU 构建，可用于数据处理兼容环境。
- [Conda create](https://docs.conda.io/projects/conda/en/latest/commands/create.html)支持按路径创建环境，环境名无需成为应用协议的一部分。
- 主线生成行为和 CUDA 12.8 配套选择沿用[vLLM 生成约定](vllm-generation.md)。
