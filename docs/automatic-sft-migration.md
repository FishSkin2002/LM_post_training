# vLLM 主环境与旧 SFT 数据自动准备

用户于 2026-11-06 确认：后续主线统一采用支持 vLLM 的环境，名称由用户自定；旧 SFT 数据兼容处理应从仅有主环境的机器启动，自动配好兼容环境、处理数据并供后续命令复用。用户随后明确：由日常训练和评测入口自动处理兼容准备；兼容环境按标准 Conda 命名环境流程创建，再用 pip 安装依赖。入口按同日确认的[项目整理约定](project-layout.md)统一为 `train.py` 与 `evaluate_checkpoint.py`。系统只需保留一套支持 CUDA 12.8 的驱动；不要求另装系统级 CUDA Toolkit 12.4。本文规定目标，按[Git 工作约定](git-workflow.md)先交付要求，再实现功能。

## 主环境与依赖入口

- 主环境负责后续新 SFT、DPO、GRPO 和生成评测。默认依赖入口以已选的 vLLM 配套组合为准，旧训练依赖单独保留作历史兼容资料，不再让默认安装指向旧栈。
- 根目录 `requirements.txt` 提供主环境的 vLLM 配套依赖。旧依赖、兼容配置及旧数据处理子进程入口集中到 `legacy/sft_data/`，供程序内部调用。
- 环境名称由用户自定，不参与功能判断；用户安装示例使用 `<环境名>` 占位符，基础命令为 `conda create -n <环境名> python=3.12 pip -y` 和 `conda activate <环境名>`，不强制覆盖用户已有的渠道配置。普通脚本使用当前 Python，检查有效依赖、设备和精度；训练结束评测继续使用同一个 Python。README 的展示范围以[编写约定](readme-writing.md)为准。
- 系统驱动与 Python 包的 CUDA 运行库分开说明。主环境使用已选的 CUDA 12.8 构建及其配套依赖；系统可只安装 Toolkit 12.8，不把安装 Toolkit 当成驱动或 Python 依赖已经满足。

## 从现有入口自动准备旧 SFT 数据

- 用户运行 `train.py sft|dpo|grpo ...` 或 `evaluate_checkpoint.py`。读取旧 SFT 来源且没有可用准备数据时，统一入口自动完成兼容环境创建、依赖安装和数据处理，然后继续本次命令。无需另外运行 `migrate_sft.py`，也无需增加启用兼容准备的命令行开关。
- 新 SFT 在主环境正常准备数据；与当前数据环境兼容的已保存来源继续正常读取。只有已识别且需要兼容处理的旧 SFT 来源才触发旧环境准备，不因缓存缺失就为每次新运行创建旧环境。
- 按现有入口支持的来源解析数据：SFT checkpoint 或 final 读取自身记录；DPO/GRPO 追溯其源 SFT；原始模型指定 `--sft-source` 时使用该来源。保留各入口原有的来源与续训检查，不额外要求用户换脚本、重命名来源或手动准备旧环境。
- 内部逻辑定位已有 Conda；找不到时明确提示安装或指定 Conda。无需绑定主环境、base 或用户主目录。
- 兼容环境用 `conda create -n <程序管理的兼容环境名> ... python=3.12 pip` 创建，尊重 Conda 配置的标准环境目录。应用不通过 `--prefix` 将环境放入 `/tmp`、项目缓存或自建前缀，也不覆盖 Conda 的环境目录配置。兼容环境名用于区分固定配置，主环境名称仍由用户自定。
- 创建后使用该兼容环境的 Python 执行 `python -m pip install ...` 安装固定旧数据处理依赖。程序通过 Conda 识别实际环境和解释器，不猜测用户安装路径，不修改主环境。仅采用当前项目已支持的旧 SFT 兼容配置，不声称能够恢复任意历史环境。
- 优先使用 CPU 版 PyTorch。兼容环境只读取、筛选、分词和核对数据，不加载模型权重进行训练或生成，不依赖 GPU，也不要求安装另一版系统 CUDA Toolkit。
- 用兼容环境的 Python 子进程执行准备数据；子进程不要求用户激活环境，也不再次递归创建环境或触发兼容准备。原有训练环境和训练进程不作为执行前提。
- 兼容环境创建与旧数据处理由统一入口调用的内部模块负责；旧环境专用 worker 与主环境读取缓存的公共逻辑分开。对用户的使用说明只保留训练和评测命令，不把内部模块作为额外的手工步骤。
- 首次自动处理前在终端明确显示正在创建兼容环境、安装依赖或准备数据，完成后继续原任务。使用明确的 Conda 渠道和 pip 安装来源；不自动接受新增服务条款。首次安装需要可用网络或相应包缓存、写入权限及足够磁盘空间。

## 原数据核对与准备结果

- 从 SFT 产物恢复原模型、分词器、提示、长度预算、数据来源和保存的划分，按对应旧数据处理方式准备数据。只接受与原 SFT 运行记录一致的结果，再写出可供主环境读取的准备数据及身份清单。
- 保留原题、监督解答、参考终值、样本与题目组顺序、原始索引及训练/验证划分；不重新挑题、不修改答案语义、不覆盖原 SFT 权重或运行记录。
- 原始数据需要从可用缓存或所记录的数据来源取得。原依赖配置无法重建、原始数据不可得或结果与 SFT 记录不一致时明确失败，不通过忽略指纹、强行套用索引或换一批题来完成数据准备。
- 输出保留经核对的原数据身份，主环境继续执行既有来源与划分校验。兼容读取旧分词器元数据时，保持实际词表、提示 token 和聊天协议一致。

## 复用与恢复

- 程序只维护自己创建的命名兼容环境，不覆盖用户现有环境；同名但未受管的环境不能直接安装或改写。区分创建中、安装中和已可用状态；只有依赖检查成功才标记可用。避免并发重复创建，失败或中断后重跑原命令可恢复，无法安全恢复时明确报出处理方式。
- 数据缓存区分准备中与完成；仅当数据核对和保存成功才发布完成结果。失败产物不作为有效缓存，原 SFT 产物始终保留。
- 数据准备完成后，普通命令可以从源 SFT 运行定位该缓存，不要求每次填写数据导出路径。DPO/GRPO 的评测仍追溯到其源 SFT；原始模型对照在指定同一 SFT 来源时复用同一批验证题。
- 保留显式指定已准备数据的能力。后续命令记录有效来源路径；已有有效缓存时不再次创建兼容环境或调用旧解释器。
- 旧来源首次准备由本次训练或评测命令自动触发，终端显示各阶段进度，用户不用切换命令。已有有效缓存时直接继续原任务，不查询或启动兼容环境；原有来源、划分和缓存读取校验照常执行。
- 兼容准备不增加历史判分核查或改写旧报告；后续新评测按[评测产物约定](evaluation-artifacts.md)保存公共快照和 JSONL，Markdown 仅由汇总生成。

## 验收与交付

- 用随机微型旧 SFT 产物从现有训练和评测入口验证首次处理：无需先运行独立数据准备脚本或添加启用开关，自动创建标准 Conda 命名环境、pip 安装、CPU 准备、核对与发布缓存，并继续原任务。环境和解释器的真实位置来自 Conda 查询，验收不借用已有旧环境冒充自动重建成功。
- 验证兼容环境确为 CPU 版，不依赖系统 Toolkit 12.4；实际依赖版本与所用兼容配置一起记录。环境名称改变不影响主流程。
- 验证主环境读取准备的数据后，词表与提示 IDs、题目/监督文本、原始索引和训练/验证划分保持一致，普通评测和后续阶段能够自动复用。
- 针对性验证已有缓存复用、并发与中断恢复，以及缺少 Conda、安装失败、原数据不一致和不完整缓存；失败不修改 SFT 产物，不将半成品标为成功。
- 验证新 SFT 与有效缓存路径不创建兼容环境，旧 checkpoint/final、DPO/GRPO 源 SFT 和原始模型对照按各自来源自动处理。兼容准备不改变所属评测格式的续跑语义，历史报告保持原样。
- README 按[编写约定](readme-writing.md)给出主环境安装与根目录脚本用法；在相关脚本下简短提示首次读取旧 SFT 产物可能自动创建 CPU 兼容环境，后续复用缓存。兼容准备的详细要求保留在本文，不要求用户执行独立命令或指定兼容环境前缀。验收区分模拟子进程检查与真实自动建环境验证，不启动真实大模型训练或大模型判分。
