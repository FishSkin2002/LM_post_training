# 脚本接口精简约定

用户于 2026-11-09 确认以下最小改动范围。本文规定目标接口，当前实现与交付状态见[进展记录](../progress.md)；按[Git 工作约定](git-workflow.md)先合入要求，再实施功能。现有算法、模型、样本格式、数据划分、判分及产物职责沿用各自约定。

## 入口与公开参数

| 入口 | 原名称 | 目标名称 |
| --- | --- | --- |
| 生成及一二级评测 | `evaluate_checkpoint.py` | `evaluate.py` |
| 三种训练的断点恢复 | `--resume-from-checkpoint` | `--resume` |
| 汇总评分运行的继续处理 | `--resume-from` | `--resume` |
| SFT 加训的权重来源 | `--continue-from` | `--source` |
| DPO、GRPO 的 SFT 权重来源 | `--sft-source` | `--source` |
| 原始模型对照的评测依据 | `--sft-source` | `--source` |
| 原始模型选择 | `--model-name` | 合入 `--checkpoint` |
| 手工指定已准备 SFT 数据 | `--prepared-sft-data` | 删除公开选项，内部自动定位保留 |

公开接口使用新名称，不新增旧名称别名。第三方 Trainer 的参数名称、已有运行记录字段和内部缓存格式不随 CLI 更名机械修改；已有模型产物仍按现有校验读取。

## 训练入口

- 保留 `train.py sft|dpo|grpo`。新 SFT 未指定来源时从原始模型开始；SFT 加训使用 `--source`，并继续要求 `--additional-epochs` 指定本次追加轮数。
- DPO、GRPO 的新训练使用 `--source` 指向已完成 SFT 的 `final/`，两者保持独立。SFT 加训沿用现有已保存 SFT 适配器来源能力；本轮不支持 SFT→DPO→SFT 等任意阶段往返。
- 各阶段 `--resume` 选择本阶段未完成的完整断点，与 `--source` 互斥；原有模型、配置、训练状态和依赖版本校验保留。加训与新训练继续创建新运行，恢复继续使用原目录和进度。
- 汇总的 `--resume` 选择已有评分运行，与 `--evaluation` 互斥；其余 API、重试及只汇总行为沿用现状。独立生成评测继续按相同命令和输出位置自动续跑，不新增评测续跑开关。

## 数据准备环境

- `train.py` 的三种模式均提供 `--env current|legacy`，默认 `current`。此参数只选择数据准备使用的环境，不切换模型训练或生成引擎所在的主环境。
- `current` 使用当前环境准备所需数据，按现有机制复用匹配缓存；该选择下不创建、安装或调用旧兼容环境，也不因来源不兼容而自动回退。当前环境无法满足原数据校验时明确报错。
- `legacy` 在确需准备数据时使用项目支持的固定旧环境；按已有 Conda、pip 与 CPU worker 机制定位或创建环境。首次新训练也能按所选环境准备数据，不要求先有旧训练产物。
- 开关覆盖相应训练方法需要执行的首次数据准备。已有兼容结果优先复用，不为读取缓存再创建环境；记录实际数据准备环境，来源数据继续保持原身份和划分校验。
- `evaluate.py` 不新增数据环境覆盖选项；评测依据产物记录，沿用已有环境判断与数据准备流程。本轮不增加任意历史环境重建能力。

## 评测模型与配置

- `evaluate.py` 必须指定 `--checkpoint`。取值为 `Qwen/Qwen3-4B-Instruct-2507` 时评测原始 Qwen，不加载本项目 LoRA；取值为本地 `final/` 或 `checkpoint-<step>/` 时读取本项目后训练产物。
- 本地训练产物须通过现有运行记录、适配器和分词器检查；SFT、DPO、GRPO 类型从记录确定，不根据目录名字猜测。错误路径或不完整产物明确报错，不回退为原始模型。原有模型缓存加载策略保留。
- 原始 Qwen 没有本项目训练记录，默认沿用当前 SFT 评测配置，保留显式 `--config`。可选 `--source` 沿用原有 SFT 来源能力，对齐该次 SFT 保存的评测配置和验证集划分，与 `--config` 互斥；它不选择模型权重。
- 后训练产物自动读取自身保存的评测配置与验证集；DPO、GRPO 使用其记录的 SFT 评测依据。此时不接受 `--source`，不开放额外配置来源覆盖。其余生成设置、批次、题数和输出选项沿用现有用途。

## 删除手工数据参数的边界

- 只删除公开的 `--prepared-sft-data` 及 CLI 传递；保留内部对已有运行记录路径、运行目录缓存及公共 Hugging Face 缓存的读取能力。
- 指定评测 checkpoint 后，继续自动取得对应数据配置、原划分及已有缓存，保留身份校验；不能因删除公开参数而丢失内部定位能力。
- 不新增数据存储体系、不搬缓存、不额外导出一份完整数据集。缓存缺失、失效绝对路径、缺失公共评测快照和完整运行跨机器搬移的恢复逻辑均不在本轮扩展；原有缺失处理行为保留。

## 验收与配套同步

- 核对三种训练、SFT 加训、评分继续处理的新参数与互斥关系，保留完整断点恢复及结束自动评测/汇总。
- 核对两类 checkpoint 输入、原始模型 source/config 选择，以及后训练产物拒绝 source；不改变实际加载的模型权重或验证题选择。
- 核对 `current` 默认及不调用旧环境、`legacy` 显式准备、已有缓存复用和实际数据环境记录；采用合成数据或模拟子进程，不启动真实完整训练或付费 API。
- 核对删除公开数据参数后，SFT、DPO、GRPO 与原始模型对照仍能读取各自已有配置/缓存。缺失恢复的新场景不作为本轮承诺。
- 同步导入、训练后评测调用、终端继续命令和测试引用。功能实现时按[README 编写约定](readme-writing.md)同时更新 README 简明示例和[参数参考](script-arguments.md)；要求阶段不提前把未实现接口写成当前用法。
