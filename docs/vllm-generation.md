# vLLM 生成约定

用户于 2026-11-05 授权为项目全部本地补全生成入口接入 vLLM，并确认默认使用 vLLM、保留显式选择原生 Transformers 生成的能力。本文规定待实现的目标；依[Git 工作约定](git-workflow.md)，要求 PR 合入后再开展功能实现。

## 覆盖范围与启用

| 入口 | 目标行为 |
| --- | --- |
| `evaluate_checkpoint.py` | 原始模型、SFT、DPO、GRPO 产物统一支持 vLLM 与原生生成。 |
| SFT、DPO、GRPO 正常结束评测 | 完整保存 `final/` 和训练状态后，用同一公共评测入口生成。 |
| GRPO 训练采样 | 使用 TRL 的 vLLM 集成，根据当前训练策略生成每题的一组回答。 |

- 用户于 2026-11-06 确认[项目整理约定](project-layout.md)：删除独立抽样问答入口，业务代码归入 `utils/`，一二级评测共用脚本，三级大模型判分与汇总各有独立脚本；训练结束自动串联三者，手动一二级不调用三级。
- SFT 与 DPO 的训练损失、训练期间的 validation loss 不增加生成调用，仍由现有训练框架计算。二三级沿用保存的回答和既定裁判流程，不使用本地生成引擎重新生成回答。
- 公共评测使用一个生成配置入口，默认引擎为 `vllm`，可显式选 `transformers`；独立命令及训练结束评测均能选择该配置。生成配置与训练数据、模型配置、大模型判分配置分开。
- GRPO 训练生成在阶段配置中默认启用 vLLM，保留显式关闭的设置。训练采样与评测可各自选择引擎；公共评测的贪心设置不覆盖 GRPO 的温度和组内采样。
- 缺少依赖、设备不支持、引擎初始化失败或最终生成失败时明确报错。不得自动切换引擎、精度、量化或输出预算。原生选项可用于已有环境和显式 CPU 微型检查。

## 环境与依赖

- 历史原生环境固定 `torch==2.6.0`；TRL 1.16.0 声明支持 `vllm>=0.22.0,<=0.31.0`，其中 vLLM 0.22.0 的 CUDA 依赖固定 `torch==2.11.0`，不能直接追加安装并宣称兼容。已选的主环境采用 PyTorch 2.8.0/cu128、vLLM 0.10.2、TRL 0.27.2 和 Transformers 4.57.6 的配套组合，宿主驱动需支持 CUDA 12.8。
- 用户于 2026-11-06 确认以 vLLM 配套环境作为后续主线，名称可以自定。默认依赖入口随主线调整；统一训练和评测入口首次读取需要兼容的旧 SFT 来源时，自动通过标准 Conda 命名环境和 pip 配置 CPU 兼容栈、核对并保存准备数据，然后继续原命令，此后自动复用。系统不要求另装 Toolkit 12.4，具体行为与验收见[主环境与旧 SFT 数据自动准备](automatic-sft-migration.md)。
- 本轮不修改正在运行的训练环境，不安装真实模型或启动正式训练。单凭 `NVIDIA vGPU-32GB` 和显存容量不能确认物理 GPU 架构或支持的二进制构建。

## 公共评测生成

- 两种引擎均使用现有消息构造、固定 system、题目原文、分词器原生聊天模板和相同输入 token；只给 system/user 与 assistant 起始头，不提供参考答案，不添加思考段。避免引擎再次套用模板或重复插入特殊词元。
- 原始模型不加载适配器；训练产物使用其底座与指定 checkpoint/final 的实际 LoRA 权重。vLLM 支持的适配器加载方式或临时合并产物需保持原产物不变，不能只加载底座或误用初始 SFT 适配器代替 DPO/GRPO 策略。
- 保持既定底座精度和贪心解码、原生 EOS `<|im_end|>`、PAD `<|endoftext|>`、输出预算。明确设置结束规则，避免继承模型仓库中的额外停止条件。实际输出 token 数计至首个 EOS 并包含它，排除补齐 token；达到预算而无正常 EOS 时标记截断。
- 显式设置引擎运行上下文上限，容纳本次提示和输出预算且不超过模型本身上限。该设置不修改模型结构，也不缩短已配置的回答预算；不按底座最大上下文无条件预留缓存。
- 保留 `--batch-size` 的默认值 4、固定/自适应规则和题目顺序。vLLM 可以在提交的一个批次内调度，但对外返回该批每题对应的结果。生成异常后的缩小与重试仍从同一道未保存题开始；必要时清理并重建失效引擎，不能跳题或重复保存。
- JSONL 与 Markdown 继续只追加本次新题，按已有 JSONL 条数恢复，不重判、不校验、不重建旧内容。报告及新记录保存实际引擎、版本和有效生成配置；旧记录缺失这些字段时不反查，也不推断为本次引擎。切换引擎比较模型使用新的输出路径，避免混合作为同一比较结果。
- 汇总继续包含已保存题目的判分、截断、实际 token 数和耗时。初始化耗时与生成耗时分开记录，吞吐口径明确；不保证两种引擎逐字一致。正式对照统一引擎、精度、提示和解码设置。

## 训练结束后的资源交接

现有训练结束评测的调度由根目录 `train.py` 集中维护：原生评测调用根目录评测函数，vLLM 评测在方法返回后由根入口替换训练进程。具体资源释放要求如下。

- 先保存 `final/`、分词器及训练状态，再开始评测。选择原生引擎时保留复用训练模型的能力。
- 选择 vLLM 时，释放训练模型、优化器及训练期 GRPO 推理引擎占用的 GPU 资源，再从刚保存的 `final/` 建立公共评测引擎。可采用进程退出后再启动评测的方式保证释放；不能在原训练权重和训练引擎仍驻留时无条件加载第三份模型。
- 资源交接需保留训练结束的编排职责：一二级成功后继续调用独立三级和汇总；手动一二级入口仍只处理前两级。进程替换方式不能让后两步因训练进程已退出而丢失。
- 评测失败不修改或删除已保存训练结果。报错提供独立评测 `final/` 的方法，不重新训练，也不把失败改记为正确率 0。

## GRPO 训练生成

- 首版面向现有单进程、单 GPU 训练，采用 TRL 的 colocate 模式和张量并行度 1。保留原生生成选项；独立服务、多 GPU 和异步训练不属于首版范围。
- vLLM 只负责生成。参数更新继续由现有 TRL、Transformers 与 PEFT 完成，仍仅训练策略 LoRA，冻结底座和初始 SFT 参考策略，使用既定 `grpo` 损失、KL 系数及 0/1 数学奖励。
- 首次生成、每次策略更新后下一轮生成、断点恢复后的首次生成，都必须使用当前策略的有效权重。使用并验证 TRL 的权重同步机制，避免只加载初始 SFT 或前一次策略。同步后适配器和固定参考策略保持正确，失效前缀缓存及时清理。
- 固定 TRL 的 colocate 实现会创建推理模型，PEFT 同步通过临时合并再恢复适配器推送有效权重。不能承诺零额外权重显存或仅传输小适配器的开销。显存比例、运行上下文与可选 sleep mode 显式记录，取值由短测确定，不依据当前显存快照认定已足够。
- 将生成参数分别适配到对应引擎。当前原生路径的 `use_cache`、`suppress_tokens` 不能直接传入 vLLM 的 `SamplingParams`。两条路径均保持原生 EOS 停止、禁止生成 PAD，并核对返回 token 中保留 EOS；PAD 或预算耗尽不能获得正常结束奖励。
- 保持阶段配置中的每题补全数量、温度、提示/补全预算、组内归一化和梯度累积关系，不将评测的自适应批大小带入训练。显式限制推理上下文；当前预算为提示 2048 加补全 2048。
- 启用并记录固定 TRL 版本针对训练/推理概率差异的修正及其有效参数。切换引擎可能改变采样和训练轨迹，不能以目标损失名称相同宣称训练过程完全一致。
- 断点续训沿用保存的生成引擎和配置；旧 GRPO 断点缺少引擎信息时按原生生成解释，显式选择与原行为匹配的配置恢复。启用 vLLM 的新运行从 SFT `final/` 开始，不把切换引擎静默包装为原计划恢复。SFT/DPO 旧产物仍能用于新的独立生成评测。

## 验收与交付

- 离线针对性检查覆盖配置选择、缺少依赖、模板/token 边界、适配器来源、EOS/PAD、正常结束/截断、批次映射、自适应重试、按条数续跑和资源交接。生成与奖励规则已有检查继续作为回归依据，不启动完整真实 SFT/DPO/GRPO 训练。
- GRPO 检查首次与恢复后同步、更新后的策略同步、固定参考不变、损失与奖励路径、生成参数转换及配置恢复。依赖解析通过和模拟引擎通过分别报告，不能代替真实 vLLM 运行。
- 在兼容 GPU 环境对原始模型/已保存适配器完成少量实际生成，并对 GRPO 完成少量采样与参数更新，记录版本、实际设备、峰值显存及生成/更新耗时。硬件不可用时明确列出尚未完成的实测；不预先承诺速度倍数。
- 功能 PR 提供配置、配套环境依赖、统一训练及评测命令、旧环境使用原生选项的方法。要求 PR 与功能 PR 分开，已有训练结果与评测文件保留。
