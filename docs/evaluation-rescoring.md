# 分级评测与独立 API 评分约定（调整中）

用户于 2026-11-06 调整入口边界：`evaluate_checkpoint.py` 只做一二级，三级 API 与各级汇总分别提供独立脚本。训练结束的编排流程自动依次调用三者；手动一二级不自动触发三级，三级与汇总均可手动运行。三级来源参数及汇总选择方式仍在澄清，最新决定以[项目整理约定](project-layout.md)为准。判分规则沿用下述三级协议。

## 输入与范围

- 从当前评测保存的生成记录读取每题的 `question`、`reference_final_answer`、`reference_answer`、`answer`、`truncated` 及题目和轨迹索引。`reference_answer` 就是该运行已经选定的 R1 解答，不重新选择轨迹或改变验证划分。
- 一二级通过原有模型来源和默认输出路径或 `--output` 自动发现进度，无 `--input`。三级独立选择一二级结果来源，并可通过控制台参数选择已有三级评分运行继续；未选择已有运行时新建评分，重名加数字后缀。
- 保存生成回答、原始一级判分及后续各级判决；已完成生成时不重新生成回答或加载生成模型。二三级判分直接使用已保存回答，不需要重新读取整份原始数据集。
- 题数固定为本次评测预先选定的全部题，不能通过跳过题目改变分母。续跑仅读取已保存索引及判决用于恢复进度和汇总，不逐条核查历史题目、回答或判决内容。
- 原始 Instruct、SFT、DPO、GRPO 使用相同协议和裁判配置；正常训练结束保存产物后由编排流程执行完整三级及汇总。手动一二级不自动调用 API；训练中的 loss 验证及 GRPO 训练奖励保持各自流程，不调用 API。

## 按顺序判分

判分顺序固定为：全部生成及一级判定完成 → 对需要二级的题全部完成二级 → 对需要三级的题统一调用 API。一二级共用脚本，三级由训练结束编排或手动命令启动，各级完成后的总统计由独立汇总脚本生成。每个阶段内部沿固定题序逐题保存。第一级包含生成阶段已有的全部判分手段：截断检查、末框提取、格式与解析检查、对原参考的数学等价验证。后续阶段直接沿用保存的前级结果，不重新检查已完成级别的回答或分数。某一级已确定整题结果时，该题停止后续级别。未执行与执行后返回 `false` 分开记录。

| 级别 | 判定依据 | 本级通过 | 本级未通过 |
| --- | --- | --- | --- |
| 第一级 | 直接读取生成阶段已执行[基础规则](training-workflow.md#生成答案判定)后保存的判决和截断标记 | 判正确，停止 | 截断则直接判错、停止；其余未通过进入第二级 |
| 第二级 | 比较选中 R1 解答与模型回答的正式回答中的单个 boxed，沿用相同数学解析和等价配置 | 判正确，停止 | 进入第三级 |
| 第三级 | API 根据题目、参考与模型完整回答核验最终答案 | 判正确，停止 | 明确判错则错误；无法形成有效判决则待复核 |

缺少答案、格式不符合该级要求、无法解析和答案不等价均可导致本级未通过，分别保存原因。对未被第一级直接终止的题目，前两级的 `false` 表示本级未能确认正确，两级均为 `false` 时进入第三级；第二级格式问题返回本级 `false`，不能据此直接结束整题判分。

### 第二级的正式回答与单框要求

- 对 R1 解答和模型回答分别处理：有明确 `</think>` 边界时取最后一个边界之后的正文；没有边界时检查全文。
- 两边的检查范围内均须恰有一个完整、非空的 `\boxed{...}`。正确识别嵌套花括号；缺框、多框、空框、残缺框或框内不可解析时，本级返回 `false`。
- 满足结构要求后，以 Math-Verify 比较框内答案。不解析题干选项、不拼接多个框，也不按框的出现顺序尝试配对子问题。
- 单框要求只用于第二级。第一级仍使用原有末框规则；正式回答包含多个框时，仅对未被第一级终止且核验未通过的题目，因第二级无法比较而转交 API。

### 截断回答

`truncated=true` 的回答在第一级直接判错并结束。第二级与第三级均记为未执行，不比较 R1 boxed，不调用 API，也不为截断题生成 API 核查任务。

保存其截断标记、第一级终止原因及最终错误判决。即使末框完整、能与原参考或 R1 答案匹配，也不继续后续核验。

## API 裁判

- 向裁判提供原始题目、独立参考终值、所选 R1 完整解答和模型完整回答。评判最终答案是否完整回答所有子问题、是否正确；不以推导的文风或长度代替最终答案正确性。
- 允许选项字母与对应内容、等价数学表达及回答顺序不同。必须核对子问题与答案的对应关系，不能仅凭最后一个框或任意局部匹配确认整题正确。
- 参考信息可能不完整。裁判需结合题意使用参考，无法解决参考冲突或证据不足时返回无法确定，不强制二选一。
- 要求返回可解析的明确判决和简短依据。明确正确或错误时保存判决；无法确定、答复格式不符合要求、请求重试耗尽或裁判答复被截断时，保存待复核及原因。
- 记录服务地址、请求模型名、返回模型标识（如有）、提示版本、有效请求参数、原始答复、判分依据和调用次数；服务返回用量时一并记录。凭据从指定环境变量读取，密钥不写进日志或报告。
- 服务地址、模型名、凭据环境变量及请求限制由独立的裁判配置提供，具体型号由运行时明确指定。超时、最大尝试次数和输出预算须有限且可配置，不自行删减原题、参考或回答来适应请求限制。
- 密钥先从该环境变量读取。选定或新建评分后仍有未处理的三级题、且缺少密钥时，在第一次 API 请求之前通过终端隐藏输入；输入仅供本次运行使用，不落盘。已有密钥、无需三级或三级已完成时不提示。取消、空输入或无可用终端时保存已有进度并明确结束，不把未发送的题保存为待复核；选择已有评分参数可继续。

初版使用兼容的 Chat Completions 接口，提供以下服务配置入口，模型名称保留为用户配置：

| 服务 | 基础地址 | 凭据环境变量示例 | 官方接口依据 |
| --- | --- | --- | --- |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4/` | `ZAI_API_KEY` | [OpenAI API 兼容](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction) |
| DeepSeek | `https://api.deepseek.com` | `DEEPSEEK_API_KEY` | [首次 API 调用](https://api-docs.deepseek.com/) |

具体模型支持的思考、采样和结构化输出参数按所选服务文档配置，不假定两家所有参数完全相同。四种待评模型使用同一套已记录的裁判设置。

## 正确率与人工核查

- 各级汇总由独立脚本从保存的逐题判决计算，训练结束的一二三级完成后自动运行，也可手动运行。已确认正确数为最终计分正确的题数，整体正确率为该数除以全部评测题数；各级通过不重复计数，也不在旧百分比上累加。
- 即使仍有待复核题，也展示已确认正确比例、`已确认正确题数 / 总题数`、待复核数量及题目列表。待复核题保留在分母中，不能当作明确判错或从分母剔除。
- 例如总计 100 题，确认正确 70 题、尚有 5 题待复核，显示 `70.00% (70/100)` 和待复核 5 题。用户可据复核结果自行计算后续正确率。
- 截断题保留在总题数中，计为确定错误，后两级未执行；不进入 API 核查列表或待复核列表。
- 主报告保留模型与数据来源、评测设置、原有一级判分、各级结果及最终判决。生成耗时与后续判分耗时分开记录，不把 API 耗时混入原生成吞吐。
- 提供机器可读报告和逐题追加的 Markdown 阅读版，并单独追加所有进入第三级的题目。核查明细包含索引、题干、原参考终值、所选 R1 解答、模型回答、前两级未通过原因、API 判决与依据、最终计分、截断及待复核状态，并标明 API 判对、判错或待复核。

## 保存与继续处理

- 一级、二级分别保存进度并自动定位；三级保存在独立评分运行中，显式选择已有运行才续跑，否则创建新运行，原名冲突依次加 `-1`、`-2`。沿固定评测题序恢复各级位置，按已有条数或保存索引继续后面的工作；数据集 index 不连续，不用最大 index 加一定位。
- 已有 JSONL 直接使用保存结果计数；不复查历史记录内容、格式、顺序、输入身份或配置指纹，也不重判旧题。新级别只对其尚未处理的题执行本级判定，不重新执行已经完成的级别。
- 三级已保存的待复核也算已处理，普通续跑不自动重试。保留显式 `--retry-pending`，仅重试这些题的 API，沿用前两级已保存结果，并追加新的三级判决。
- Markdown 仅追加新记录，不读取、重写或从 JSONL 重建旧正文。最新汇总追加到文末；同一索引有后续复核时追加新判决，不修改之前的文字。
- 保留原有一级 `.progress.jsonl` 与 Markdown 的定位和追加规则，二级关联到同一评测输出；三级评分记录其一二级来源及裁判配置，继续原运行时沿用。已有记录继续复用，未增加历史内容核验或自动修复。
- 更换评测来源或裁判设置时由用户使用新的输出路径。API 失败不会改写原始生成记录。JSON 汇总按已保存判决更新正确率、待复核列表和 API 明细，不重新执行历史判分；完成重跑无新结果时不重复追加正文或汇总。

## 功能验收

功能实现时使用已有评测格式、微型模型和模拟 API 验证以下行为，真实裁判的判分质量另以人工核查检查：

- 第一级通过不执行后两级；非截断题第一级未通过、第二级通过时不调用 API。R1 和模型正式回答都为 B、原参考为数值的已知例子可经第二级判正确。
- 思考与正式回答重复写框时只检查正式回答；无思考边界、无框、多框、空框、残缺、嵌套分数和不可解析内容均有明确结果。多问的多个框由第二级返回 `false` 并进入 API。
- 第三级的正确、错误、无法确定、解析失败、请求失败与答复截断分别正确保存。撕纸题以及子问题逆序回答的案例作为裁判提示和人工核查样例，不以框序列充当语义核验。
- 截断题在第一级结束，即使末框与原参考或 R1 框相同也计错；验证第二级和 API 均未调用，后两级状态为未执行，且未生成 API 核查记录。
- 正确率包括 API 补判正确并保持全部题目的分母；待复核记录不丢失。验证沿用生成阶段的一级判决、各级续跑只处理新索引、历史记录不重判不复核、JSONL/Markdown 旧字节保留并只追加，以及显式重试待复核时的计分更新。
- 验证一级全量完成后才二级、二级全量完成后才 API；手动一二级不自动 API 或汇总，训练结束自动依次调用三者。一二级原命令续跑，三级选择已有运行续跑；不选择则新建，撞名加数字。已完成运行续跑禁止生成、重新判分、API 请求和密钥提示。
- 验证现有密钥直接使用、缺密钥时终端隐藏输入、无需 API 不提示，以及取消/无终端保留进度后可恢复。用两家官方兼容接口的响应结构做离线契约检查，API 配置可切换且凭据不进入产物；已有原始生成记录保持不变。无需启动真实训练或付费 API。
