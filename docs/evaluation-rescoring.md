# 分级评测与大模型判分约定

用户于 2026-11-09 确认入口边界：`evaluate.py` 只做生成及一二级判定；`summarize_evaluation.py` 默认补做三级大模型判分并汇总，`--no-api` 只汇总已保存判决。大模型判分通过 API 调用在线大模型。入口与训练编排见[项目整理约定](project-layout.md)；共享快照、JSONL 与全部 Markdown 的生成时机以[评测产物约定](evaluation-artifacts.md)为准。本文集中规定三级判分协议和计分口径。

## 输入与范围

- 题目、独立参考最终答案和选定 R1 完整解答从公共评测样本快照读取；模型回答与截断信息从回答 JSONL 读取，各级判决从判决 JSONL 读取。参考解答就是建立快照时已选定的那一条，不重新选择轨迹或改变验证划分。
- 一二级通过原有模型来源和默认输出路径或 `--output` 自动发现进度，无 `--input`。汇总阶段的来源选择与评分续跑见[项目整理约定](project-layout.md#汇总入口与继续处理)。
- 保存生成回答、原始一级判分及后续各级判决；已完成生成时不重新生成回答或加载生成模型。二三级判分使用公共快照及已保存回答，无需重新读取原始数据集。
- 题数固定为本次评测预先选定的全部题，不能通过跳过题目改变分母。续跑仅读取已保存索引及判决用于恢复进度和汇总，不逐条核查历史题目、回答或判决内容。
- 原始 Instruct、SFT、DPO、GRPO 使用相同协议和裁判配置；正常训练结束保存产物后由编排流程执行一二级，再调用默认启用 API 的汇总入口。手动一二级不自动调用 API；训练中的 loss 验证及 GRPO 训练奖励保持各自流程，不调用 API。

## 按顺序判分

判分顺序固定为：全部生成及一级判定完成 → 对需要二级的题全部完成二级 → 汇总入口按模式补做剩余三级判定并汇总。每个阶段内部沿固定题序逐题保存。第一级包含生成阶段已有的全部判分手段：截断检查、末框提取、格式与解析检查、对原参考的数学等价验证。后续阶段直接沿用保存的前级结果，不重新检查已完成级别的回答或分数。某一级已确定整题结果时，该题停止后续级别。未执行与执行后返回 `false` 分开记录。

| 级别 | 判定依据 | 本级通过 | 本级未通过 |
| --- | --- | --- | --- |
| 第一级 | 直接读取生成阶段已执行[基础规则](training-workflow.md#生成答案判定)后保存的判决和截断标记 | 判正确，停止 | 截断则直接判错、停止；其余未通过进入第二级 |
| 第二级 | 比较选中 R1 解答与模型回答的正式回答中的单个 boxed，沿用相同数学解析和等价配置 | 判正确，停止 | 进入第三级 |
| 第三级 | 大模型根据题目、参考与模型完整回答核验最终答案 | 判正确，停止 | 明确判错则错误；无法形成有效判决则待复核 |

缺少答案、格式不符合该级要求、无法解析和答案不等价均可导致本级未通过，分别保存原因。对未被第一级直接终止的题目，前两级的 `false` 表示本级未能确认正确，两级均为 `false` 时进入第三级；第二级格式问题返回本级 `false`，不能据此直接结束整题判分。

### 第二级的正式回答与单框要求

- 对 R1 解答和模型回答分别处理：有明确 `</think>` 边界时取最后一个边界之后的正文；没有边界时检查全文。
- 两边的检查范围内均须恰有一个完整、非空的 `\boxed{...}`。正确识别嵌套花括号；缺框、多框、空框、残缺框或框内不可解析时，本级返回 `false`。
- 满足结构要求后，以 Math-Verify 比较框内答案。不解析题干选项、不拼接多个框，也不按框的出现顺序尝试配对子问题。
- 单框要求只用于第二级。第一级仍使用原有末框规则；正式回答包含多个框时，仅对未被第一级终止且核验未通过的题目，因第二级无法比较而转交三级大模型判分。

### 截断回答

`truncated=true` 的回答在第一级直接判错并结束。第二级与第三级均记为未执行，不比较 R1 boxed，不调用 API，也不将截断题列入三级核查明细。

保存其截断标记、第一级终止原因及最终错误判决。即使末框完整、能与原参考或 R1 答案匹配，也不继续后续核验。

## 大模型判分

- 向裁判提供原始题目、独立参考终值、所选 R1 完整解答和模型完整回答。评判最终答案是否完整回答所有子问题、是否正确；不以推导的文风或长度代替最终答案正确性。
- 允许选项字母与对应内容、等价数学表达及回答顺序不同。必须核对子问题与答案的对应关系，不能仅凭最后一个框或任意局部匹配确认整题正确。
- 参考信息可能不完整。裁判需结合题意使用参考，无法解决参考冲突或证据不足时返回无法确定，不强制二选一。
- 要求返回可解析的明确判决和简短依据。明确正确或错误时保存判决；无法确定、答复格式不符合要求、请求重试耗尽或裁判答复被截断时，保存待复核及原因。
- 记录服务地址、请求模型名、返回模型标识（如有）、提示版本、有效请求参数、原始答复、判分依据和调用次数；服务返回用量时一并记录。凭据从指定环境变量读取，密钥不写进日志或报告。
- 服务地址、模型名、凭据环境变量及请求限制由独立的裁判配置提供，具体型号由运行时明确指定。超时、最大尝试次数和输出预算须有限且可配置，不自行删减原题、参考或回答来适应请求限制。
- 密钥先从该环境变量读取。选定或新建评分后仍有未处理的三级题、且缺少密钥时，在第一次 API 请求之前通过终端隐藏输入；输入仅供本次运行使用，不落盘。已有密钥、无需三级或三级已完成时不提示。取消、空输入或无可用终端时保存已有进度并明确结束，不把未发送的题保存为待复核；选择已有评分参数可继续。

初版使用兼容的 Chat Completions 接口，提供以下服务配置入口，模型名称保留为用户配置：

| 服务 | 基础地址 | 凭据环境变量示例 | 官方接口依据 |
| --- | --- | --- | --- |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4/` | `ZAI_API_KEY` | [OpenAI API 兼容](https://docs.bigmodel.cn/cn/guide/develop/openai/introduction) |
| DeepSeek | `https://api.deepseek.com` | `DEEPSEEK_API_KEY` | [首次 API 调用](https://api-docs.deepseek.com/) |

具体模型支持的思考、采样和结构化输出参数按所选服务文档配置，不假定两家所有参数完全相同。四种待评模型使用同一套已记录的裁判设置。

## 正确率与人工核查

- 各级指标由 `summarize_evaluation.py` 从固定快照和保存的逐题判决计算。默认先完成尚未处理的三级；`--no-api` 直接汇总选定评分的现有结果。不同评分运行的判决不混合。
- 一级累计正确数只计一级通过，二级累计正确数加上二级补判正确，三级累计正确数再加上本次三级判正确；各级累计正确率均除以固定全部评测题数。各级通过不重复计数，也不在旧百分比上累加。
- 三级中断时可显式使用 `--no-api` 汇总部分结果，明确展示已确认正确、明确错误、待复核、未处理及固定总题数。未处理不当作明确错误或待复核，不缩小分母；该模式不生成回答、重新判分、请求 API 或索取密钥。
- 即使仍有待复核题，也展示已确认正确比例、`已确认正确题数 / 总题数`、待复核数量及题目列表。待复核题保留在分母中，不能当作明确判错或从分母剔除。
- 例如总计 100 题，确认正确 70 题、尚有 5 题待复核，显示 `70.00% (70/100)` 和待复核 5 题。用户可据复核结果自行计算后续正确率。
- 截断题保留在总题数中，计为确定错误，后两级未执行；不进入三级核查列表或待复核列表。
- 生成耗时与后续判分耗时分开记录，不把 API 耗时混入原生成吞吐。配置只在元数据中保存；分卷问答的总指标、逐题三阶段结果及两类 API 核查清单按[阅读报告约定](evaluation-artifacts.md#问答分卷与-api-核查)组织，核查清单通过链接定位原文。

## 保存与继续处理

公共快照、元数据、回答/判决 JSONL、普通续跑、显式重试及汇总后替换 Markdown，统一依照[评测产物约定](evaluation-artifacts.md)。首个 API 请求前保存评分来源和裁判配置，进度不依赖汇总或 Markdown 成功生成；API 失败不改写原始回答。新运行与续跑的入口规则见[汇总入口](project-layout.md#汇总入口与继续处理)。

## 功能验收

功能实现时使用已有评测格式、微型模型和模拟 API 验证以下行为，真实裁判的判分质量另以人工核查检查：

- 第一级通过不执行后两级；非截断题第一级未通过、第二级通过时不调用 API。R1 和模型正式回答都为 B、原参考为数值的已知例子可经第二级判正确。
- 思考与正式回答重复写框时只检查正式回答；无思考边界、无框、多框、空框、残缺、嵌套分数和不可解析内容均有明确结果。多问的多个框由第二级返回 `false` 并进入三级大模型判分。
- 第三级的正确、错误、无法确定、解析失败、请求失败与答复截断分别正确保存。撕纸题以及子问题逆序回答的案例作为裁判提示和人工核查样例，不以框序列充当语义核验。
- 截断题在第一级结束，即使末框与原参考或 R1 框相同也计错；验证第二级和 API 均未调用，后两级状态为未执行，且未生成三级核查记录。
- 正确率包括大模型补判正确并保持全部题目的分母；待复核记录不丢失。验证沿用生成阶段的一级判决、各级续跑只处理新索引、历史判决不重判不复核，以及显式重试待复核时的计分更新。存储和 Markdown 验收以[产物验收](evaluation-artifacts.md#功能验收)为准。
- 验证一级全量完成后才二级、二级全量完成后才执行三级大模型判分；手动一二级不启动汇总，训练结束自动依次调用一二级与默认启用 API 的汇总入口。已完成评分复用记录，不再次生成、判分、请求 API 或提示密钥。
- 验证来源新建与已有评分续跑互斥，续跑沿用原裁判配置，多份评分保持独立；`--no-api` 只汇总指定来源的已保存结果。
- 验证三级中断或首个请求前取消后，使用 `--no-api` 可生成部分报告。例如总计 100 题，一二级已确认正确 60 题，大模型已处理 20 题，其中正确 10、错误 8、待复核 2，另外 20 题未处理；应显示三级累计 `70/100`、错误 8、待复核 2、未处理 20。中断本身不生成 Markdown，正常默认汇总等全部应处理题有保存判决后生成。
- 验证现有密钥直接使用、缺密钥时终端隐藏输入、无需大模型判分时不提示，以及取消/无终端保留进度后可恢复。用两家官方兼容接口的响应结构做离线契约检查，API 配置可切换且凭据不进入产物；已有原始生成记录保持不变。无需启动真实训练或付费 API。
