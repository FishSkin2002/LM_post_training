# Qwen3 Instruct 数学训练约定

用户于 2026-10-29 确定：项目一以 `Qwen/Qwen3-4B-Instruct-2507` 为起点，在 OpenR1-Math-220k 的 R1 生成解答上做 LoRA SFT，后续再开展 GRPO。本约定替代此前的 Base 普通文本 QA 路线；文件路径保留，供现有文档入口引用。

## 模型与范围

- 当前真实训练与训练前对照固定使用 `Qwen/Qwen3-4B-Instruct-2507`。它已经接受官方后训练；“原始模型”仅表示尚未接受本项目训练，不表示未经官方 SFT 或推理训练。
- 原始 Instruct 经本项目 LoRA SFT 得到后续训练起点。DPO 与 GRPO 分别从同一个 SFT 产物开始，使用各自的[训练约定](post-training-workflow.md)。本文件规定 SFT 的模型、数据和样本格式。
- 旧 Base 配置和运行产物保留作历史资料，不用于新版流程的恢复、加训或训练前后比较。接口验证使用临时随机微型模型，不以另一种真实模型的结果代替主线结果。

## 数据来源与统一入口

- 主 SFT 来源为 `open-r1/OpenR1-Math-220k` 的 `default/train`。`problem` 是题目原文，监督目标选自 `generations`；`answer` 是独立的参考最终答案，`solution` 保留作来源资料，不用作主监督目标。
- 按轨迹索引对齐 `correctness_math_verify`、`correctness_llama` 和 `is_reasoning_complete`：至少一个正确性标记为真且轨迹完整，才可作为候选。字段缺失或长度不一致明确报错；最终答案正确性标记不代表逐步推理验证。
- 每题固定选择原列表中首条合格轨迹，保存原始记录和轨迹索引；不把一题多条轨迹全部展开为独立题目。没有合格轨迹或最终答案不可用于当前评测的题目筛除，并统计原因。
- 保留选中 R1 解答的推理、LaTeX 和既有 `<think>...</think>`，不重写成上游 `solution`，也不靠追加参考 `answer` 修补不完整或错误解答。筛选需保证有可提取的完整 boxed 最终答案。
- 保留 GSM8K 读取接口，供后续测试等用途。其原题、去计算器注释后的完整解答和从 #### 提取的参考终值分开保存；清理只删除整个 `<<...>>` 子串，其余解答保持，不为它伪造 R1 思考轨迹。当前主线不要求重新训练 GSM8K 或迁移旧训练产物。
- 先用单文件 `math_data.py` 统一数据入口，内部按来源处理。数据模块提供自然题目、监督解答、参考终值、题目组及来源标识；聊天包装、分词、EOS、损失标签和模型输出评分各由对应层处理。各数据源独立逻辑明显增长后再拆文件，公共入口保持。
- 数据准备输出原始、合格和筛除数量、重复题目组、选中轨迹长度分布及当前长度规则。使用显式配置的训练长度上限；超长样本筛除而不截断推理或最终答案。正式训练前根据实际分词长度确定预算并保存，不无说明沿用旧流程的 1024-token 预算。

## 原生聊天模板与消息职责

沿用该模型分词器自带的聊天模板，不自定义模板或改词表。固定 system 内容如下，末尾不额外添加空行：

```text
Solve the following math problem step by step.
End your response with the final answer in \boxed{...}, for example \boxed{4}.
```

每条训练样本包含三条消息：

| 角色 | 内容 |
| --- | --- |
| system | 上述固定任务与最终答案格式要求。 |
| user | `problem` 原文，不加 Question/Answer 前缀、不拼接提示或清理题干。 |
| assistant | 选中的完整 R1 生成解答。 |

- 训练和 loss 验证以完整三消息、`add_generation_prompt=False` 渲染。原始 Instruct 和 SFT 生成均只给相同 system/user，以 `add_generation_prompt=True` 加入 assistant 起始头；不提供参考解答，不预填 `<think>` 或空思考段。
- 使用原生 EOS `<|im_end|>`；PAD 为 `<|endoftext|>`。模板已经提供消息结束标记，不再手工追加旧 Base EOS。生成只在新输出的原生 EOS 停止，并记录达到预算的截断。
- 训练、loss 验证、预览、抽样及独立评测共用同一消息构造和模板。运行信息记录实际模板、固定 system、题目/解答处理、EOS/PAD 和模型身份，随产物保存，恢复和加训时校验。
- 分词时避免重复添加特殊词元；监督边界以实际分词后的前缀对齐为准，不按字符数猜测。框架的默认助手掩码不能代替本项目所需的标签核验。

## 监督损失

- system、user、assistant 起始头、padding 和模板结束后的格式换行不计 loss；选中 R1 正文（含思考、正式解答、最终答案）及一个 assistant EOS 接受同一常规因果语言模型交叉熵监督。
- labels 与输入等长，未监督位置为 -100，由模型执行一次移位。训练及 loss 验证使用教师强制，不先自由生成再计算文本损失；不因另一种表达与参考答案数学等价而清零 SFT loss。
- 最终答案数学等价只用于独立生成评测或未来 RL 奖励，不评价每步推导，也不把思考段出现或回答变长算作数学能力提升。

## LoRA 与已确认的优化

- 沿用 PEFT LoRA 与 Transformers Trainer，仅训练适配器。LoRA 参数、学习率、批量和轮次使用少量显式配置，不预设最优或自动调参。
- 在目标 GPU 支持且微型验证正常的条件下，以 BF16 加载底座并进行 BF16 训练计算；LoRA 可训练参数保持 FP32。原始模型和 SFT 生成使用一致的底座精度及计算设置，均保存在运行或评测记录中。
- 采用非重入激活检查点 `use_reentrant=False`，训练时关闭 KV cache；生成使用自己的缓存设置。核验梯度、参数更新及训练/生成设置恢复，不把训练禁用缓存无意延续为生成限制。
- 上述两项优化已获用户确认；量化、额外注意力后端、梯度累积、offload、专用优化器等不自动加入。硬件或精度不支持时明确说明，不静默改变比较条件。
