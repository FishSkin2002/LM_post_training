# 项目整理与评分入口约定

用户于 2026-11-06 通过 grill-with-docs 确认业务目录使用 `utils/`、训练统一为 `train.py`、删除抽样问答入口；随后确认评分边界：一二级共用脚本，三级与汇总各有独立脚本。只有训练结束的编排流程自动串联三者，手动一二级不触发三级。三级新建与续跑分别使用 `--evaluation` 与 `--resume-from`；汇总选定一次三级评分，支持其中断后的部分结果。本文以这些最新决定替代此前“评测命令自动运行三级”的方案。

当前实现与交付状态见[进展记录](../progress.md)。依[Git 工作约定](git-workflow.md)，先合入要求 PR，再从最新远程 main 开展功能实现。

## 入口与目录

- 根目录保留 `train.py`、`evaluate_checkpoint.py`、`judge_evaluation.py`、`summarize_evaluation.py` 四个业务入口，分别负责训练、一二级评测、三级评分和结果汇总。其余根部业务脚本及公共模块归入 `utils/`，内部按训练、评测、数据、生成等职责组织；偶尔使用的数据准备和环境检查脚本也放入该目录。
- `tools/` 保持 Agent 工具、测试与 smoke 检查的职责，不接收本次搬迁的业务实现。`legacy/sft_data/` 保留独立旧依赖、CPU worker 及其配置，继续供程序内部调用。
- 删除 `sample_checkpoint.py` 的随机抽样问答功能及入口。将评测所需的共享生成依赖指向公共生成模块，保留 `evaluate_checkpoint.py --num-samples` 对固定前 N 道验证题的评测能力。
- `train_sft.py`、`train_post_sft.py` 的入口由 `train.py` 替代。原 `rescore_evaluation.py` 中的二级判分移入一二级评测，API 判分移入独立三级脚本，各级汇总移入独立汇总脚本；一二级仍无 `--input`，自动按输出位置续跑。
- 同步调整模块导入、配置和默认输出路径定位、训练结束的评测启动、legacy worker 及测试引用。已有模型、run、数据缓存和评测产物保留；README 在功能阶段按[编写约定](readme-writing.md)更新实际目录与命令。

## 统一训练

- 使用 `python train.py sft|dpo|grpo ...` 选择阶段，默认加载该阶段已有配置。保留各阶段原有参数语义、YAML 结构及保存的运行元数据兼容能力。
- 提取重复的模型加载、来源读取、运行目录、保存、日志及结束评测逻辑；SFT、DPO、GRPO 的数据、Trainer、损失和算法参数保留各自实现。算法可以分文件或共处模块，避免从用户入口脚本反向导入公共函数。
- 保留现有训练用途：SFT 支持新训练、完整断点恢复及完成后加训；DPO/GRPO 支持从 SFT 开始及本阶段完整断点恢复。本次不新增算法用途或更改损失、参考策略、奖励和划分。
- 各训练阶段正常结束先完整保存 `final/` 与训练状态，再由训练结束的编排流程自动依次运行全量一二级、独立三级、独立汇总。训练中 loss 验证、GRPO 奖励与手动中断行为沿用现有约定。
- 原生生成可复用已加载模型；vLLM 继续按[资源交接约定](vllm-generation.md#训练结束后的资源交接)释放训练资源，再从保存产物评测。结束评测失败后可单独重跑评测命令，不重新训练。

## 一二级评测与继续处理

- OpenR1 的一次一二级命令先全量生成并逐题做一级判定，再对需要二级的全部题完成二级。一二级全部完成后，该命令结束；不自行调用三级或汇总脚本。
- 一二级各自保存进度；相同来源、题数与输出路径重跑时，自动找到关联进度，从各级尚未保存的位置追加。一级完成跳过生成，二级完成直接结束。
- 续跑只依据固定题序、索引或已保存条数及判决恢复位置，不重新判定历史级别、不复查已保存回答、格式、顺序或身份。不以非连续的原始数据集 `index` 最大值加一推算位置。
- 一二级沿用原默认输出定位和显式 `--output` 能力，不要求用户指定输入报告或增加启用续跑的开关。JSONL 和 Markdown 只追加新记录；最终各级统计由独立汇总脚本计算。
- 逐级判分、截断、待复核、裁判配置及报告以[三级判定约定](evaluation-rescoring.md)为准。三级沿用已有 OpenR1 范围；GSM8K 的既有读取和基础评测能力保留，本次不新增跨数据源的 R1 重评。
- 评测按进度追加不取消训练断点、数据划分及缓存读取本身的来源校验。

## 独立三级评分与汇总

- 三级脚本只读取已完成的一二级结果，对仍需裁判的题调用 API，不重新生成回答或执行前两级。训练结束自动调用，也可平时手动调用；手动一二级命令不调用它。
- 三级新建用 `--evaluation <一二级结果>` 指定回答来源；续跑用 `--resume-from <已有三级评分目录>`，两种来源互斥。续跑自动读取该运行记录的一二级来源与裁判配置，沿原目录按保存索引继续追加，不复查历史回答或判决；已完成的运行不再次请求 API。
- 不选择已有评分运行时，始终创建新的三级评分。评分名冲突时依次加 `-1`、`-2` 等数字后缀；同一批回答可以保留多次独立评分，既有运行不被覆盖。
- 各级结果汇总单独提供脚本，仅使用保存的一二级结果和三级判决计算统计、生成报告，不加载模型、不重新判分。训练结束的一二三级全部完成后自动调用，也可单独手动运行。
- 自动顺序为训练保存 → 一二级完成 → 三级完成 → 汇总。某阶段失败或中断时保留已保存产物；可手动运行对应脚本继续，不通过重新训练来恢复评分。

## 汇总选择与部分结果

- 手动汇总使用 `--scoring <三级评分目录>` 显式选定一次评分，连同它关联的一二级结果计算各级累计指标。同一批回答的其他评分运行保持独立；训练结束自动传入本次新建的评分目录。
- 支持三级尚未完成时手动汇总部分结果，分别展示已确认正确、明确错误、待复核、未处理及固定总题数。尚未处理与已请求但无有效判决分开，均保留在总分母中。
- 自动汇总仅在一二三级全部处理完成后执行；已保存待复核算已处理。手动评分不自动启动汇总，汇总也不触发评分或索取密钥。
- 首个 API 请求前即保存评分来源、裁判配置与固定评测范围，使请求前取消或请求中断后的已有运行能够续跑和手动汇总。

以下为功能阶段需要实现的命令形式：

```bash
python judge_evaluation.py --evaluation /path/to/evaluation.json
python judge_evaluation.py --resume-from /path/to/scoring-run
python summarize_evaluation.py --scoring /path/to/scoring-run
```

## 三级密钥输入

- 恢复进度后，确有尚未处理的三级题时，先读取裁判配置指定的密钥环境变量；缺少密钥则在第一个 API 请求前使用终端隐藏输入，类似密码输入。
- 已有密钥、无需三级或三级已完成时不提示输入。不在训练开始时索取密钥，不使用桌面弹窗。输入的密钥仅供本次运行使用，不写配置、日志或报告。
- 用户取消、空输入或没有可用交互终端时，明确提示并结束本次评分，保留前两级和已完成三级的进度；未发送请求的题不因此记为已处理的待复核。选择已有三级运行后继续；不传该参数仍按新建评分处理。

## 功能验收

- 用微型模型和已有针对性检查验证三阶段训练入口、配置选择、SFT 加训、断点恢复与结束评测，保证旧训练产物及自动旧数据准备继续可用。
- 验证根部入口收敛、公共函数导入、配置/默认输出定位、legacy worker、环境检查和测试引用，不需要保留旧入口才能运行。
- 用模拟 API 验证一级未全量完成时不执行二级、二级未全量完成时不能开始三级；训练结束自动串联一二级、三级和汇总，手动评分脚本仅执行自己的级别。
- 验证一二级自动发现进度、三级显式选旧运行续跑，以及不选旧运行的新建/撞名加数字。历史 JSONL/Markdown 字节不变；已完成运行续跑不生成、不重判、不调用 API 或索取密钥。
- 验证汇总独立于生成和评分，由训练结束编排传入本次评分，或手动通过 `--scoring` 选定一次评分；同一批回答的多次评分不混合。三级中断和首个请求前取消均可手动部分汇总，未处理与待复核分开且总分母不变。
- 验证环境密钥复用、终端隐藏输入、取消/无终端后恢复，以及密钥不进入产物。判分和指标验收继续依照三级判定约定；无需真实大模型训练或付费 API。
