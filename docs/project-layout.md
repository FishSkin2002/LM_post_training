# 项目整理与评分入口约定

用户于 2026-11-06 确认业务目录使用 `utils/`、训练统一为 `train.py`、删除抽样问答入口；于 2026-11-09 更新评分边界：一二级共用 `evaluate_checkpoint.py`，`summarize_evaluation.py` 默认补做 API 三级判定并汇总，可用 `--no-api` 只汇总已有结果。训练结束自动依次调用这两个入口，手动一二级不触发汇总。本文替代此前独立三级与独立汇总两个脚本的目标。

当前实现与交付状态见[进展记录](../progress.md)。依[Git 工作约定](git-workflow.md)，先合入要求 PR，再从最新远程 main 开展功能实现。

## 入口与目录

- 根目录保留 `train.py`、`evaluate_checkpoint.py`、`summarize_evaluation.py` 三个业务入口，分别负责训练、生成及一二级评测、可选 API 三级判定与汇总。其余根部业务脚本及公共模块归入 `utils/`，内部按训练、评测、数据、生成等职责组织；偶尔使用的数据准备和环境检查脚本也放入该目录。
- 根目录脚本直接包含自身的入口逻辑。`train.py` 定义 CLI、共用训练函数和训练结束后的评测调用；各训练方法分别位于 `utils/training/`。`evaluate_checkpoint.py` 整体包含生成评测流程；`summarize_evaluation.py` 整体包含 API 判定、指标汇总和阅读报告生成流程。
- 根目录业务函数可以被其他流程导入复用，命令行执行由 `if __name__ == "__main__"` 保护。被调用时使用保存的配置和产物，不因导入自动解析参数或启动训练、生成和判分。
- `tools/` 保持 Agent 工具、测试与 smoke 检查的职责，不接收本次搬迁的业务实现。`legacy/sft_data/` 保留独立旧依赖、CPU worker 及其配置，继续供程序内部调用。
- 删除 `sample_checkpoint.py` 的随机抽样问答功能及入口。将评测所需的共享生成依赖指向公共生成模块，保留 `evaluate_checkpoint.py --num-samples` 对固定前 N 道验证题的评测能力。
- `train_sft.py`、`train_post_sft.py` 的入口由 `train.py` 替代。现有 `rescore_evaluation.py` 更名并调整为 `summarize_evaluation.py`，不再另建 `judge_evaluation.py`；二级判分由一二级评测完成。一二级仍无 `--input`，自动按输出位置续跑。
- 公共快照位置、各评测文件职责及 Markdown 时机以[评测产物约定](evaluation-artifacts.md)为准；公共快照独立于训练运行目录，所有模型评测共用。
- 同步调整模块导入、配置和默认输出路径定位、训练结束的评测启动、legacy worker 及测试引用。已有模型、run、数据缓存和评测产物保留；README 在功能阶段按[编写约定](readme-writing.md)更新实际目录与命令。

## 统一训练

- 使用 `python train.py sft|dpo|grpo ...` 选择阶段，默认加载该阶段已有配置。保留各阶段原有参数语义、YAML 结构及保存的运行元数据兼容能力。
- 共用的模型加载、适配器保存、训练器基础行为、运行环境校验及结束评测调用放在 `train.py`，由训练方法按需导入；数据读取、运行目录和日志等工具继续复用各自模块。SFT、DPO、GRPO 的 Trainer、损失和算法参数保留各自实现；DPO 与 GRPO 分别使用独立训练模块，各自从 SFT 开始，互不依赖对方运行或产物。
- 保留现有训练用途：SFT 支持新训练、完整断点恢复及完成后加训；DPO/GRPO 支持从 SFT 开始及本阶段完整断点恢复。本次不新增算法用途或更改损失、参考策略、奖励和划分。
- 各训练阶段正常结束先完整保存 `final/` 与训练状态，再由训练结束的编排流程依次运行全量一二级、默认启用 API 的汇总入口。训练中 loss 验证、GRPO 奖励与手动中断行为沿用现有约定。
- 原生生成可复用已加载模型；vLLM 继续按[资源交接约定](vllm-generation.md#训练结束后的资源交接)释放训练资源，再从保存产物评测。结束评测失败后可单独重跑评测命令，不重新训练。

## 一二级评测与继续处理

- OpenR1 的一次一二级命令先全量生成并逐题做一级判定，再对需要二级的全部题完成二级。一二级全部完成后，该命令结束；不自行调用三级或汇总脚本。
- 一二级各自保存进度；相同来源、题数与输出路径重跑时，自动找到关联进度，从各级尚未保存的位置追加。一级完成跳过生成，二级完成直接结束。
- 续跑只依据固定题序、索引或已保存条数及判决恢复位置，不重新判定历史级别、不复查已保存回答、格式、顺序或身份。不以非连续的原始数据集 `index` 最大值加一推算位置。
- 一二级沿用原默认输出定位和显式 `--output` 能力，不要求用户指定输入报告或增加启用续跑的开关。输出按[机器数据职责](evaluation-artifacts.md#机器数据的职责)组织为元数据、回答和判决；此阶段不生成 Markdown。
- 逐级判分、截断、待复核、裁判配置及报告以[三级判定约定](evaluation-rescoring.md)为准。三级沿用已有 OpenR1 范围；GSM8K 的既有读取和基础评测能力保留，本次不新增跨数据源的 R1 重评。
- 评测按进度追加不取消训练断点、数据划分及缓存读取本身的来源校验。

## 汇总入口与继续处理

- `summarize_evaluation.py` 读取已完成的一二级结果及关联公共快照；默认对仍需裁判且尚未处理的题调用 API，随后计算各级累计指标并生成阅读报告，不加载生成模型或重做前两级。
- 新评分使用 `--evaluation <一二级评测来源>`；已有评分使用 `--resume-from <已有评分运行>`，两种来源互斥。续跑沿用该运行保存的来源和裁判配置，已完成评分不再次请求 API。未选择已有运行时新建评分，重名依次加 `-1`、`-2`；不同评分结果保持独立，共用回答和前级记录。
- `--no-api` 对选定来源只汇总已有判决，不请求 API、不重试待复核或索取密钥，允许查看三级中断后的部分结果。固定分母与未处理、待复核、明确错误的口径见[分级判定约定](evaluation-rescoring.md#正确率与人工核查)。
- 首个 API 请求前保存评分来源与裁判配置，已有 JSONL 即可恢复；中断时只保存机器进度。Markdown 只在汇总正常结束时生成，具体规则见[生成时机](evaluation-artifacts.md#汇总与-markdown-生成时机)。
- 自动顺序为训练保存 → 一二级完成 → 汇总入口补做三级并生成报告。某阶段失败或中断时保留已保存产物，可手动继续对应流程，不通过重新训练恢复评分。

## 三级密钥输入

- 恢复进度后，确有尚未处理的三级题时，先读取裁判配置指定的密钥环境变量；缺少密钥则在第一个 API 请求前使用终端隐藏输入，类似密码输入。
- 已有密钥、使用 `--no-api`、无需三级或三级已完成时不提示输入。不在训练开始时索取密钥，不使用桌面弹窗。输入的密钥仅供本次运行使用，不写配置、日志或报告。
- 用户取消、空输入或没有可用交互终端时，明确提示并结束本次评分，保留前两级和已完成三级的进度；未发送请求的题不因此记为已处理的待复核。选择已有运行后继续；使用 `--no-api` 可查看已有结果。

## 功能验收

- 用微型模型和已有针对性检查验证三阶段训练入口、配置选择、SFT 加训、断点恢复与结束评测，保证旧训练产物及自动旧数据准备继续可用。
- 验证根部入口收敛、公共函数导入、配置/默认输出定位、legacy worker、环境检查和测试引用，不需要保留旧入口才能运行。
- 用模拟 API 验证一级未全量完成时不执行二级、二级未全量完成时不能开始三级；训练结束依次调用一二级和默认启用 API 的汇总入口，手动一二级不调用汇总。
- 验证一二级自动发现进度、汇总显式选旧评分续跑，以及不选旧运行的新建/撞名加数字。已有回答和判决 JSONL 仅追加；已完成评分不生成、不重判、不调用 API 或索取密钥。
- 验证默认汇总与 `--no-api` 的调用边界、评分选择和独立性，三级中断及首个请求前取消后可用 `--no-api` 查看部分结果。公共快照、JSONL 职责、分卷和核查链接按[产物验收](evaluation-artifacts.md#功能验收)验证。
- 验证环境密钥复用、终端隐藏输入、取消/无终端后恢复，以及密钥不进入产物。判分和指标验收继续依照三级判定约定；无需真实大模型训练或付费 API。
