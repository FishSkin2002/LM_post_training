# DPO 与 GRPO 训练约定

## 实验起点

- DPO 使用 `python train.py dpo ...`，GRPO 使用 `python train.py grpo ...`；二者是独立训练方法，各自从 SFT 开始，互不依赖对方运行或产物。业务实现归入 `utils/`，按[项目整理约定](project-layout.md)分别组织两种方法的训练实现。

- 本项目进行对照实验时，DPO 和 GRPO 各自从同一次 `configs/training/sft.yaml` 运行保存的 SFT `final/` 初始化。显式传入产物路径，从中读取底座、LoRA 结构、分词器和 SFT 评测来源。两种方法各有训练配置、输出目录、优化器、调度器和步数。
- 各阶段更新从 SFT 加载的策略 LoRA，冻结 `Qwen/Qwen3-4B-Instruct-2507` 底座。DPO 的参考策略固定为初始 SFT。GRPO 启用参考策略约束时使用同一初始 SFT。策略和参考可以共享冻结底座。
- 原生路径使用已通过微型检查的 TRL 1.16.0、Transformers 和 PEFT；vLLM 路径按[vLLM 生成约定](vllm-generation.md)选择并验证配套依赖，不将旧环境的检查结果冒充新组合已经通过。沿用 [SFT 约定中的精度与梯度检查点](qwen3-base.md#lora-与已确认的优化)。阶段配置显式记录批量、长度、步数和算法参数。

## DPO 偏好数据

- 使用 [tasksource/prm800k_dpo](https://huggingface.co/datasets/tasksource/prm800k_dpo) 的 `solution/train`。使用原始 `prompt` 作题目，保留 `chosen` 和 `rejected` 的偏好方向、推导正文和最终答案内容。
- `chosen` 取最后一个独立 `# Answer` 标题后的非空单行终值。若一对数学分隔符恰好包裹整个终值，取分隔符内的内容。将标题和尾部答案替换为 `\boxed{原答案}`，保留末尾已经符合该格式的完整答案框。例如 `$\frac{1}{4}$` 转成 `\boxed{\frac{1}{4}}`。
- `chosen` 须能定位终值、形成一个花括号完整的 `\boxed{...}`，且框内答案通过现有 Math-Verify 解析。终值跨行、花括号残缺或仍含未转义的数学分隔符时，排除整对。分别记录 `chosen` 结构筛除和解析筛除数量。
- `rejected` 使用最后一个完整、独立的 `# Answer` 标题。标题后有非空内容时，将标题与尾部替换为 `\boxed{原内容}`，去掉内容首尾的分隔空白，保留内部换行、数学分隔符和残缺片段。
- 若 `rejected` 的末尾只有截断标题（如 `# Answe`），或 `# Answer` 后只有空白，删去末尾标题并保留其前面的解答。全文无答案标题时保留原文。答案格式与解析的筛除只看 `chosen`。
- DPO 使用与 SFT 相同的 system 和原生聊天模板，要求逐步解题并用 `\boxed{...}` 给出最终答案。损失作用于两个回答各自的正文与一个原生 EOS。校验提示的分词边界，按转换后的两个完整序列的长度上限筛除超长偏好对。
- 使用标准 DPO sigmoid 损失。记录训练 loss 和偏好指标，统一生成评测按本文件的对照协议进行。

## GRPO 数学数据与奖励

- 使用 [Skywork/Skywork-OR1-RL-Data](https://huggingface.co/datasets/Skywork/Skywork-OR1-RL-Data) 的 `default/math`。取 `prompt` 中的用户题目，解码 `reward_model.ground_truth` 内的 JSON 答案列表，统计并筛除没有任何可解析参考的题目。难度标签仅供了解数据来源。
- 生成沿用 SFT 的 system、题目原文和原生聊天模板。参考答案只传给奖励函数。每题生成多条回答，奖励沿用[最终答案判定](training-workflow.md#生成答案判定)。正常 EOS 结束且末个 `\boxed{...}` 与任一可解析参考数学等价时奖励为 1，其余为 0。参考答案为 `1/4` 时，正常结束的 `\boxed{0.25}` 得 1 分。
- 使用 TRL 的 `grpo` 损失与组内奖励归一化。显式设置每题采样数、提示和回答词元预算及参考约束系数，校验生成批量与组大小的整除关系。超长提示在生成前筛除。训练记录奖励、输出长度和截断率。
- 训练生成默认使用 vLLM colocate，并保留显式原生选项；当前策略同步、EOS/PAD、显存预算和恢复配置以[vLLM 的 GRPO 约定](vllm-generation.md#grpo-训练生成)为准。损失计算和参数更新继续由现有训练框架执行。

## 共用生成评测

- 原始 Instruct、SFT、DPO、GRPO 使用指定 SFT 运行保存的 OpenR1 验证题及顺序，以及相同的 SFT 提示、原生模板、精度、解码预算和评分。训练数据身份和共用评测来源分开记录，评测题依照 SFT 产物的原有数据选择与划分恢复。
- 各方法准备训练数据时，对训练题和 SFT 验证题去除首尾空白，再把连续空白折叠为一个空格。排除所得字符串相同的训练题或偏好对，分别记录排除数。匹配范围限归一化后完全一致的题干。模型输入使用原始题干。
- 正常结束后先保存各阶段 `final/`，再由训练结束编排依次调用[一二级评测](training-workflow.md#独立生成评测)和默认启用 API 的[汇总入口](project-layout.md#汇总入口与继续处理)。训练中记录各阶段训练指标，不调用大模型判分。手动一二级从 `--checkpoint` 选择训练产物，完成后不主动调用汇总。公共快照与阅读报告遵循[评测产物约定](evaluation-artifacts.md)，报告区分 SFT、DPO 和 GRPO。

## 产物与验收

- DPO、GRPO 的训练配置和产物按阶段隔离。`run.json` 记录阶段、输入 SFT 产物、训练数据版本和指纹、筛除计数与训练配置，以及单独的 SFT 评测来源。各阶段分别在自己的目录记录 TensorBoard 事件、保存适配器、分词器和训练断点。
- `final/` 保存更新后的策略。完整断点另存恢复所需的优化器、调度器、随机状态和训练进度。恢复前校验训练配置、数据及输入 SFT 的身份，从原始 SFT 权重恢复冻结参考，从当前阶段断点恢复训练策略和状态。
- DPO 的训练数据指纹包含答案格式处理规则。更换规则时，从源 SFT `final/` 开始新运行。恢复断点须匹配保存时的答案格式规则。
- 使用随机微型模型分别验证 DPO 与 GRPO 的训练用途、DPO 偏好回答的转换和 EOS、GRPO 奖励及截断边界、共用评测题精确排除、参考冻结、策略更新、保存恢复，以及四个模型来源评测题的一致性。用固定版本 PRM800K 全量核对转换范围、原答案内容和筛除计数，并检查已有 SFT 产物的兼容性。
- 正式长度、生成组大小和显存预算由训练机短测确定。本轮实现与验证可在 SFT 运行期间完成，正式运行待 SFT `final/` 可用。
