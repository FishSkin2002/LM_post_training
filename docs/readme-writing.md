# README 与脚本参数参考编写约定

本文件集中记录用户截至 2026-11-09 确认的使用文档展示要求。README 提供简短用途与命令示例，[脚本参数参考](script-arguments.md)说明完整参数。模型、训练和评分的详细规则由各自约定维护；当前实现状态见[进展记录](../progress.md)。

## 板块顺序

1. 标题使用“大语言模型数学推理后训练”，下方用一句话说明项目用途；实验报告目录单独突出显示，可附已有报告链接。
2. 项目目录：根目录总览，下设 configs 和 outputs 的目录说明。
3. 聊天格式：独立板块，只展示项目实际使用的格式。
4. 回答正确性判定：与聊天格式同级，介绍判断模型回答是否正确的方法，简述参考答案核验、R1 解答核验和大模型判分。
5. 环境准备：简短安装命令和执行所需的说明。
6. 主要脚本使用说明：按根目录脚本分类，再按用途分类；在本章节链接脚本参数参考。

README 使用纯文字和 Markdown 排版，不使用 emoji 或表情符号。实验报告入口用加粗文字和普通引用块等标识保持醒目。

## 目录展示

- 根目录总览只展示根部文件和文件夹，文件夹不展开；每个条目都用简短注释说明用途，包括协作规则、术语和规划文件。
- configs 单独展示到文件夹，不列具体配置文件；其用途注释包含训练、开发、大模型判分和公共生成配置。
- outputs 使用 training 中的一次训练运行为例，展开到文件并逐项注释；`checkpoint-<step>/` 只保留一行断点用途注释，`final/` 及其余产物目录展开。
- 区分仓库内产物和配置指定的外部训练机路径；按保存逻辑写示例，标明按条件生成的文件及可变文件名，不把示例当作已存在的完整运行。
- 目录展示不改变产物含义：完整训练断点另含续训状态，`final/` 保存模型产物；实际保存规则见[训练运行约定](training-workflow.md)。

## 脚本说明范围

- 主要脚本部分只介绍根目录运行脚本，每个脚本先写一句简短用途介绍；utils、tools 内的入口及 TensorBoard 等配套工具不列入该板块。
- DPO 与 GRPO 分别给出新训练、断点恢复的用途、命令和必要参数；每种方法的用法完整，不让读者从另一方法的示例自行替换推断。
- README 每个用途只保留简短说明及填好必需参数的命令，说明路径如何替换和本用途必需的来源条件；完整参数及详细运行条件放在脚本参数参考。
- 多余训练原理、内部实现及大段环境说明直接从使用文档删除，不为承接这些内容另建文档。
- README 和脚本参数参考均以当前已实现的入口为准；未来目标、开发进度和待实施安排写在对应约定或进展文件中。修改入口或参数时同步这两份使用文档。

## README 中的命令示例

- 每个用途给一条示例指令；该用途必需的参数和值直接写入示例，路径占位符就近说明如何替换。
- 参数是否必填以本用途和实际脚本为准；成对必填参数，以及实现重试或只汇总等用途所需的开关，都写入对应示例。
- README 的脚本说明不放参数表或完整可选参数清单，通过本章节的链接查阅脚本参数参考。

## 脚本参数参考

- 在 [docs/script-arguments.md](script-arguments.md) 按脚本和用途分类，与 README 用途对应；每个用途列全必需参数及适用的可选参数，同一参数在不同用途中的规则分别就近说明。
- 参数表固定使用三列：`参数`、`默认值`、`可填内容及作用`。必需参数也列入表格，不能因已在 README 示例出现而省略。
- 默认值写清省略参数时的实际取值或确定规则。由配置决定时标明对应配置项；枚举、数值等简短默认值直接展示当前取值，并说明自选配置可改变它。由运行来源或设备条件决定时，明确对应规则。
- 没有默认值且本用途必填的参数注明“无；本用途必填”。开关注明默认是否开启；本用途必须开启时同时标明，不把用途要求误写成脚本的默认值。
- 可填内容完整说明枚举值、数值范围、路径所指对象或开关写法，并简述整体用途；无须逐项解释每个枚举值的差别。互斥、配对或仅限某用途的约束就近写明。
- 用途已经选定的互斥来源参数在各自用途下说明；本用途不生效的参数说明原因，不列为有效可选项。所有参数、默认值和约束均核对当前脚本与配置。

## 用词与环境示例

- 判分方式称“大模型判分”，首次介绍可说明“通过 API 调用在线大模型”。回答正确性判定简介不写具体服务或模型名称；脚本操作中的配置路径、密钥变量等以实际配置为准。
- “手动”只用于说明由用户单独启动命令，与训练后自动调用相区分；不使用“手动 API”描述判分方式。三级规则以[分级判定约定](evaluation-rescoring.md)为准。
- `prepared-sft/` 简述为“读取旧 SFT 产物时自动准备的数据缓存”；在脚本参数参考的相关脚本处说明首次可能自动创建 CPU 兼容环境、后续复用缓存，避免反复使用缺少上下文的“迁移”。
- `requirements.txt` 简述为 Python 环境依赖，正常安装使用该文件，无需反复强调“唯一入口”。
- 创建和激活环境的示例均使用 `<环境名>` 占位符，并说明替换为相同的自选名称；基础示例为 `conda create -n <环境名> python=3.12 pip -y` 和 `conda activate <环境名>`，不额外强制指定 Conda 渠道。程序内部受管兼容环境的安装规则见[旧 SFT 数据自动准备约定](automatic-sft-migration.md)。
