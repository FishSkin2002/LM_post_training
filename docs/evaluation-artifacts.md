# 评测产物与汇总报告约定

用户于 2026-11-09 确认：生成及一二级判定阶段只保存机器数据；`summarize_evaluation.py` 默认补做 API 三级判定，正常结束后才生成全部 Markdown。本文确定产物、共享样本和报告时机，替代旧的整份评测 JSON、独立三级脚本和 Markdown 逐题追加要求。判分协议与计分口径见[分级判定约定](evaluation-rescoring.md)，入口与训练编排见[项目整理约定](project-layout.md)。当前实现状态见[进展记录](../progress.md)。

## 公共评测样本快照

- 在生成前，将本次选定的全部评测样本按固定题序保存为单个 JSON：`outputs/evaluation-datasets/<快照标识>.json`。位置相对于项目根目录解析，与各训练运行目录分离，不受启动命令所在目录影响。
- 快照包含每题题干原文、独立参考最终答案、选定的完整监督解答、样本编号和来源记录/轨迹定位信息。不展开同题未使用的其他轨迹；不包含待评模型的生成回答或判决。
- 原始 Instruct、SFT、DPO、GRPO 使用相同样本、题序与参考内容时复用同一份快照。内容发生变化时使用新标识创建新快照，保留旧快照；每份评测只记录引用，不把快照复制到各训练输出目录。
- 快照同时确定评测全集、顺序和总题数，取代独立的 `indices.json`。来源说明与快照引用进入元数据，不在其他报告头部再展开长索引列表。
- 二三级判分与阅读报告从快照取得题目和参考，从回答记录取得模型输出，不重新下载或选择原数据集中的参考解答。共享快照属于需要保留的运行数据；缺失时明确报错，不用数据集当前 `main` 替换它。

## 机器数据的职责

JSONL 用于程序读写及恢复进度，不要求人工可读。每份评测使用以下职责划分，不再生成嵌入全部问答的汇总 JSON：

| 文件 | 保存内容 |
| --- | --- |
| `metadata.json` | 模型及产物来源、快照引用、提示/模板、生成设置、引擎、环境；首次确定的裁判设置及提示版本。 |
| `answers.jsonl` | 样本编号、模型生成的完整回答、词元数、截断、实际批大小和生成耗时等每题数据。题干及参考内容只在快照中保存。 |
| `judgments.jsonl` | 按样本和级别保存的判决、原因及该级耗时；三级记录附 API 原始答复、返回模型标识、用量和调用/重试详情。 |

- 配置在对应阶段首次确定时保存一次，续跑复用。尚未选择 API 时不伪填裁判配置；第一次实际启用三级时登记一次。引擎、环境、静态设置不进入逐题记录或 Markdown。
- 各级判决写入同一份 `judgments.jsonl`，每条只追加本级新增信息；二级不复制一级，三级不复制前两级，也不再另存嵌套的前级判决副本。缺少的级别在汇总时展示为 `not_run`，与执行后未通过区分。
- 原始回答和判决分别落盘并刷新。回答已保存但一级判决尚未保存时，恢复只补缺失判决，不重新生成回答。所有阶段按已保存样本及级别定位剩余工作，不以最大原始索引加一推算位置。
- 直接使用已有完整 JSONL 记录恢复；不增加历史正文、顺序、身份或判决的逐条核验及自动修复。训练断点和数据准备原有来源校验保持各自职责。
- 多次评分保持独立，汇总使用选定评分的三级判决及其关联的一二级结果。新评分仅新增本次配置与判决，复用已有快照、回答和前级记录，不复制整套问答。裁判设置变化时新建评分，已有评分续跑沿用原设置。
- 普通续跑复用已处理结果，待复核也算已处理。显式 `--retry-pending` 只补做所选运行中的待复核三级判定并追加新结果；汇总取该运行每题的最新有效记录，既有判决历史保留在 JSONL 中。

## 汇总与 Markdown 生成时机

1. `evaluate.py` 创建或复用共享快照，保存元数据与回答，完成全部一级后再完成需要的二级判定。该入口不调用 API、不生成 Markdown。
2. `summarize_evaluation.py` 读取已完成的一二级结果。默认仅对仍需三级且尚未处理的题调用 API，保存判决后计算各级累计指标；使用 `--no-api` 时直接汇总已有结果，不请求 API、重试待复核或索取密钥。
3. 默认模式下，全部应处理三级题都有记录后生成 Markdown，允许存在待复核。`--no-api` 正常结束也生成 Markdown，未执行三级的题仍为未处理，不当成明确错误或待复核。
4. API 阶段中断、取消或异常退出时只保存机器进度，不生成或刷新 Markdown。需要查看部分结果时，显式运行 `--no-api` 生成当前阅读版；已有阅读版维持上一次成功汇总的内容。
5. 再次成功汇总时，从快照和最新保存结果重新生成、替换对应阅读版；不向旧正文追加同题的新版本。已完成评分的重复汇总不生成回答、不重判历史级别、不重复调用 API。

Markdown 仅由汇总入口生成，不作为续跑依据。汇总不加载生成模型、重新分词或重新选择监督轨迹。

## 问答分卷与 API 核查

| 阅读产物 | 内容 |
| --- | --- |
| `answers-0001.md`、`answers-0002.md` 等 | 固定题序的题目、参考最终答案、选定监督解答、模型回答及每题三阶段判定结果；总指标只放第一卷。 |
| `api-decided.md` | API 已明确判对或判错的样本编号、判决、原因，以及指向问答分卷中原题的链接。 |
| `api-pending.md` | API 无法确定或调用后未形成有效判决的样本编号、原因，以及指向问答分卷中原题的链接。 |

- 问答分卷上限可配置，默认每卷 100 题；超过后创建下一卷，同一道题的原文保持完整。每题有稳定锚点，API 清单用相对链接定位所在分卷和题目。
- 问答卷的指标区域仅放全体问答的总指标和逐题三阶段判定结果，不放判定原因、配置、环境或 API 调用详情。完整问答原文只在问答分卷出现一次。
- 两类 API 清单按最新三级状态互斥分组，只有实际进入 API 且已形成保存记录的题进入清单；未处理和前级已终止的题不混入待复核清单。两份清单均不复制题干、参考或模型回答。
- API 原始响应、用量和重试详情只保存在对应三级 JSONL 记录中，不额外复制为另一份审计文件。Markdown 只展示人工查看需要的判决、理由和链接。
- 人工复核本轮只提供清单与定位链接，人工结论回写和重新计分留后续独立步骤。

## 功能验收

后续实现使用合成样本、临时目录和模拟 API 检查以下行为；本要求 PR 不运行模型或真实付费 API。

- 同样本、题序与参考内容跨模型复用公共快照；不同内容新建快照。工作目录变化不改变默认公共位置，所有评测只保存引用；移除原数据集后仍能依据快照继续判分和生成报告。
- 题干/参考只在快照，回答只在回答 JSONL，逐级判决只保存本级内容；引擎、环境与配置不逐题重复，无独立 indices 文件或整套问答汇总 JSON。
- 生成、一二级以及 API 中断时不产生 Markdown；回答与判决之间中断后不重复生成回答，续跑只处理尚未保存的级别；已完成运行不再请求 API。
- 默认汇总仅对剩余三级题请求 API，`--no-api` 在缺少密钥时也可正常汇总部分结果；未处理、待复核与明确错误分别统计，分母保持快照总题数。
- 问答在 100/101 题边界正确分卷，上限可配置；总指标只出现于第一卷，题目及完整回答不截短，逐题无原因或配置；所有 API 链接都定位到正确的分卷和稳定锚点。
- API 判对/判错与待复核清单正确分类，复核重试后按最新状态刷新；正文只在问答卷出现，API 调用详情仅存 JSONL。重复汇总不累加同题、旧汇总或重复 API 请求。

本次要求面向后续产物格式；历史报告保留，不批量迁移、删除或重新判分。README 在功能实现时按[README 编写约定](readme-writing.md)同步实际命令和目录。
